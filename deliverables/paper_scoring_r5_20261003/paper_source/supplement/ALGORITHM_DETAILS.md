# 算法实现与复算说明

四段伪代码随工程交付；论文正文集中介绍模型、求解原理和实验。下文保留R4对应的调用、停止及失败处理逻辑。


程序读取天气、建筑、设备和价格配置，输出设备容量、逐时运行方案及费用与排放结果。`src/heatplan/`保存数据检查、模型和求解函数，`scripts/`与命令行入口负责组织实验。城市数据与模型代码分开存放，更换天气或设备目录时可以复用已有约束；数值单位、允许范围和数据所属对象在计算前检查。

2026年10月2日，候选版`v11.12.0rc6`在独立CPython 3.12.7环境通过252项不重复测试，并复算19个连续2880小时案例，包括9个温控、6个固定设备LP和4个容量耦合案例。发布资料保留依赖包版本、运行命令及独立核验结果。本次论文修订引用这批已有记录。

复算时，先用文件校验码确认数据和配置版本，再按保存的参数运行，最后核对逐时结果、费用和约束偏差。以下四段伪代码分别说明场景批量计算、代表日权重校正、费用与碳排放比较、管网校核反馈；源文件位置见下表，路径以 GitHub 仓库根目录为起点。

| 算法 | 实际源文件 |
|---|---|
| 1 场景清单 | `src/heatplan/unified_cli.py`、`src/heatplan/io.py`、`src/heatplan/reporting.py` |
| 2 权重校正 | `src/heatplan/hard_weight_calibration.py`、`src/heatplan/representative_adoption.py`、`scripts/bdg2_hard_weight_confirmation.py` |
| 3 多目标计算 | `src/heatplan/model.py`、`src/heatplan/experiments.py`、`scripts/run_competition_frontier.py` |

## 场景批量计算与结果输出
**算法1：场景清单主程序。**输入：场景列表、配置及逐时数据文件、求解时限和允许的最优性间隙（gap）；输出：各场景方案、比较表和实际运行参数。

| 行 | 操作 |
|---|---|
| 01 | 读取场景列表并定位文件；检查gap参数及可选政策设置。 |
| 02 | **对每个**场景条目，创建独立输出目录并读取配置路径。 |
| 03 | **若**提供分阶段规划文件，**则**调用相应函数，保存阶段与投资表。 |
| 04 | **否则**检查配置和逐时数据；按可选情景设置生成输入并再次检查。 |
| 05 | 装配`HeatPlanningModel`，调用`solve`，导出方案。 |
| 06 | 汇总该场景状态；**若**配置政策评价，**则**保存评价表。 |
| 07 | **结束循环**；保存比较表，以及命令行时限和gap参数的实际应用规则。 |
| 08 | 输出运行摘要并**返回**控制台；异常由对应调用报告。 |

`export_results`输出费用与碳排放摘要、投资、调度及已附加的建筑检查表。本文实验脚本还保存数据与代码校验码、失败记录和运行清单（manifest），用于反查每个表值来自哪次计算。

## 能量守恒下的权重校正与检查
**算法2：固定实际日权重。**输入：每日完整观测、已选日的负荷曲线、初始频数权重、权重下限和检查规则；输出：所选权重、求解状态及检查结果。

| 行 | 操作 |
|---|---|
| 01 | 检查数据长度、有限非负值与完整日数；固定已选日的负荷曲线。 |
| 02 | **若**下界总和超出日数，**则**标记不可行；**若**均值为零，**则**标记指标未定义。 |
| 03 | 汇总两组数据的负荷取值，计算累计分布；用辅助变量表达绝对差。 |
| 04 | 以最小归一$W_1$为目标，施加能量、日数等式和权重下界，求解LP。 |
| 05 | **若**求解成功，**则**独立重算能量、日数、下界及目标残差。 |
| 06 | 检查候选权重对应的能量、分布、峰值与爬坡；同时检查原频数权重。 |
| 07 | **若**候选全部通过，**则**采用候选；**否则**回退频数并保留两者失败原因。 |
| 08 | **返回**权重、所用方法、是否通过检查及原因；保存各案例记录。 |

回退只是改用原频数权重，该方案仍要单独通过检查。程序同时保存两种方案的结果，说明问题出在能量、分布还是峰值覆盖。通过这些统计检查后，还需按原时间顺序检验室温和储热状态。

## 费用与碳排放方案的生成
**算法3：多目标计算入口。**输入：设备配置、供热舒适要求、逐时数据、时限及容差；输出：端点、碳帽候选、非支配方案及失败记录。

| 行 | 操作 |
|---|---|
| 01 | 保存数据与代码版本，记录费用包含哪些项目、碳排放如何计算。 |
| 02 | **对每个**主目标$F_C,F_E$，新建模型并求主目标可行值$v$。 |
| 03 | 若有可行值，加入上限$v+\delta_{\mathrm{abs}}+\delta_{\mathrm{rel}}|v|$，求次目标。 |
| 04 | 审核并保存两阶段状态、界、gap、轨迹；异常保存为失败项。 |
| 05 | **结束循环**；**若**两端点有效且碳区间有序，**则**生成五档碳帽。 |
| 06 | **对每档**碳帽，添加有效容差，独立最小化配置总费用。 |
| 07 | 保存约束检查及目标组成；成功方案入结果表，异常入失败表。 |
| 08 | **结束循环**；按容差去重并剔除样本中的支配点。 |
| 09 | 输出方案与失败表；全档成功时生成完整运行清单，**返回**退出码。 |

专用扫描把碳价设为零，算法3的赛事入口保留配置中的碳价和其他费用项；上下界均与所在阶段的实际目标对应。

## 管网运行方式的检查与重算
**算法4：网络反馈函数。**输入：候选模式、温压等阈值、逐时需求与计算预算；输出：通过方案及各轮记录，或失败原因。

| 行 | 操作 |
|---|---|
| 01 | 建立候选模式及启用变量，约束同时运行容量，初始化排除集合。 |
| 02 | **对每轮**预算内的迭代，求解并独立复算开启时的温压等量及小时能量。 |
| 03 | **若**调用异常，**则**保存已有计算与失败原因后报告异常。 |
| 04 | 保存检查结果、求解状态及新增不合格方式，写出本轮记录。 |
| 05 | **若**全部通过，**则返回**方案、调度、候选目录、检查与各轮记录。 |
| 06 | **若**没有新增可排除方式，**则**报告失败并附上已有记录。 |
| 07 | **对每个**新增失败模式，在所有时段固定启用变量为零，更新集合。 |
| 08 | **结束循环**；报告达到最大轮数，由调用入口保存失败文件。 |

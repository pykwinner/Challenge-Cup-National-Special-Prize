# 关键参数补齐优先级清单

日期：2026-10-01。范围为当前 11.11.1 主工程，只读核查后登记。本轮为研究与计划文件；配套[结构化登记](research_parameters_20261001.json)，没有修改业务模型或原输入。

共有 24 项。P0 表示相关主案例和结论放行之前必须明确；P1 表示一天内可以保留为有说明的简化或未完成扩展。优先级是项目内部执行顺序，不是附加官方评分项。生物质、冷热年度约束等只在所选案例启用时成为必要项。

“可用来源”引用[权威来源索引](权威方法与数据来源索引.md)及[结构化来源](research_sources_20261001.json)中的 ID。来源能支持参数范围、方法或核算身份，不意味着提供了本项目数值；空缺可用有物理意义的典型假设并登记，不等待主办方数据。**没有经验数据时不赋概率、不声称统计置信区间；敏感性低/中/高仅为说明过的探索情景。**字段前写“拟新增”表示当前接口未完整实现，不得视为已有能力。

服务面积、舒适标准、时钟、初末态与冷热路线先共同冻结；H/C/得热、设备曲线和成本整理可并行。完整季和适用年度在同投资、明确初态时逻辑独立，默认按资源排队，具体见[依赖说明](并行实施依赖与研究依据.md)。基准和方案必须提供同一面积、时段、舒适度及冷热服务。

## 逐项处理与验收

### P01 逐时时钟与供暖服务窗口

- **字段/单位：**timestamp；planning.time_step_hours；scope.start_inclusive/end_exclusive/timezone；h；带时区ISO时间。
- **当前证据：**weather_manifest.yaml为LST；heating_season.py要求准确半开时间窗。
- **进入模型前：**先用同点短段UTC/LST匹配确定偏移；NASA按15度经带，不按任意分钟转换；北京时对齐电价、占用；确定一段数据完整的跨年窗口。
- **不能据此声称：**不能把LST直接标为北京时；不能把一个项目服务期说成全市法定期，或平移年份后仍称该年真实日期。
- **敏感性或验收：**时间差独立计算应有行数；每预期小时唯一；跨日、跨年及闰日检查。
- **最小交付：**time_basis.md + scope.json + chronology_audit.json。责任：数据角色；验证角色复核；P0：完整季前必须冻结。


### P02 气象温湿风与辐射输入

- **字段/单位：**outdoor_temp；relative_humidity；风/辐射列按当前CSV字典；°C；%或0–1明确；m/s；辐射按原参数单位。
- **当前证据：**data/public_sources已有三地2020—2024；派生solar_heat_availability不等于实测设备可用率。
- **进入模型前：**保留原始响应、参数单位、产品版本、地点与哈希；检查湿度百分数转换、辐射小时平均/累计区别；缺失处理显式记录。
- **不能据此声称：**不能称为城市站点或热表实测；产品间一致不等于实际负荷预测准确。
- **敏感性或验收：**逐列缺测/范围/连续性检查；保留低温极值；同源小样本逐值核对。
- **最小交付：**weather_manifest.json + field_dictionary.csv。责任：数据角色；P0：使用既有数据；其他天气源仅可选交叉核查。


### P03 服务建筑面积与聚合范围

- **字段/单位：**policy.served_floor_area_m2；拟新增building_id/area_m2映射；m²。
- **当前证据：**现有3节点为plant/district_a/district_b；已有总面积政策字段，不等于逐楼面积表。
- **进入模型前：**确定原型代表一个小区、典型楼栋还是建筑组；面积、户数、峰值负荷、层级映射同步；若采用典型面积须登记工程假设。
- **不能据此声称：**不能把异地或能源站全部服务面积压到三节点后声称真实逐栋计算；OSM footprint不直接等于供暖建筑面积。
- **敏感性或验收：**各楼/组面积汇总等于服务面积；参数放大时负荷、热容、投资缩放合理；不能重复计楼层面积。
- **最小交付：**building_register.csv + aggregation_map.csv。责任：数据角色；建筑角色；P0：所有单位面积、室温和公平基准都依赖它。


### P04 建筑总传热系数H

- **字段/单位：**拟新增 building.H_kw_per_k；当前没有绝对室温RC的对应完整字段；kW/K。
- **当前证据：**现有thermal_inertia.recovery_loss_per_hour不能直接证明H；公开标准公告只确认规范，未读取具体热工表。
- **进入模型前：**按围护结构U×面积及通风换热推导H，或用有说明的典型参数；区分整栋与单位面积；保留推导过程，勿由年能量随意拟合唯一H。
- **不能据此声称：**不能把标准上限当实际建筑值；不能凭峰值负荷同时识别H和C；不得称已实测标定。
- **敏感性或验收：**H>0；稳态供热与H×温差及得热平衡一致；不同保温组结果方向合理；设置明确探索区间。
- **最小交付：**building_thermal_parameters.csv + H_derivation.md。责任：建筑物理角色；P0：绝对室温核心；可用透明典型值，不等待外部数据。


### P05 建筑有效热容C

- **字段/单位：**nodes.thermal_inertia.<grade>.thermal_capacity_kwh_per_c；拟新增RC有效热容；kWh/K。
- **当前证据：**旧模型各温级设置thermal_capacity_kwh_per_c，以移时up/down驱动。
- **进入模型前：**审查旧参数对应服务面积与物理边界；建立一栋/一组的有效热容，避免把high和low两份虚拟热容重复加给同一建筑。
- **不能据此声称：**不能把旧热容数值直接贴到新RC模型就声称物理已验证；不能称典型热容为当地实测。
- **敏感性或验收：**C>0；τ=C/H单位为小时；无供热降温、恢复升温及增大C延缓响应；独立重算离散方程。
- **最小交付：**C_assumption_register.csv + thermal_response_checks.csv。责任：建筑物理角色；P0：绝对室温与初态所必需。


### P06 占用时段与舒适温度上下限

- **字段/单位：**occupancy_a/b；拟新增T_min/T_max；旧max_temperature_deviation_c；0–1或布尔；°C。
- **当前证据：**S3已有占用、setback及温差代理，尚非绝对室温；乌市公示不能代表武汉或所有建筑。
- **进入模型前：**区分有人/无人、居住/办公及服务合同假设；冻结绝对上下限与统计口径；旧代理约束迁移时防止舒适度双计。
- **不能据此声称：**不能以温差代理零违规证明实际室温达标；不能将某地居民要求套所有城市。
- **敏感性或验收：**独立计算欠温/过温度时和最长连续违规；失供导致实际受热减少及温度响应；基准与方案相同标准。
- **最小交付：**comfort_contract.yaml + comfort_audit.csv。责任：建筑角色；案例角色；P0：比赛明确关注必要室温约束。


### P07 内部得热

- **字段/单位：**拟新增building.internal_gain_kw(t)；kW。
- **当前证据：**尚未发现主案例独立逐楼人员/设备/照明实测时序。
- **进入模型前：**由占用与单位面积典型得热构造，列明散热进入空气或等效节点的边界；当日可使用声明的简化曲线或零得热下界情景。
- **不能据此声称：**不能将假设曲线标注实测；零内部得热并不自动证明所有经济结果保守。
- **敏感性或验收：**无供热时有得热不应降温更快；占用一致；对低/中/高透明假设进行至少方向性比较。
- **最小交付：**internal_gain_assumptions.yaml。责任：建筑角色；数据角色；P0：需明确模型是否计入；详细人群行为P1。


### P08 太阳得热

- **字段/单位：**拟新增building.solar_gain_kw(t)；不得直接使用solar_heat_availability作为建筑得热；kW。
- **当前证据：**现有solar_heat_availability按全年辐射分位数归一化，是设备可用率代理。
- **进入模型前：**从有单位的辐射、窗面积、方向/遮挡和太阳得热系数派生；无详细几何时采用明确简化系数及敏感性。
- **不能据此声称：**不能把0–1可用率直接当kW；OSM建筑轮廓不能证明窗墙比、遮挡或实测得热。
- **敏感性或验收：**夜间无太阳得热；单位换算、面积缩放正确；不得同时重复计入气象负荷代理和RC得热。
- **最小交付：**solar_gain_derivation.md + gain_timeseries.csv。责任：建筑角色；数据角色；P0：得热边界需明确；完整遮阳几何P1。


### P09 热泵COP与除霜曲线

- **字段/单位：**sources.carnot_efficiency/cop_min/cop_max/source_temp_column；defrost_*；kW热/kW电；°C；无量纲系数。
- **当前证据：**当前按Carnot效率、温差、湿度和限幅预计算；没有已核厂家全工况曲线。
- **进入模型前：**保留供水温级与室外温度两个维度；区分名义COP、季节性能、除霜折减；用假设范围而非未核厂商数字。
- **不能据此声称：**不能以国家能效标准名称证明当前每小时COP准确；不得把季节系数当全部小时恒定COP。
- **敏感性或验收：**逐时重算电输入=热输出/COP；冷段、除霜带、截断连续性检查；关键假设上下扰动。
- **最小交付：**cop_parameter_register.csv + cop_checks.csv。责任：设备模型角色；P0：设备转换核心；厂家新曲线非当日阻塞。


### P10 热源容量、低温降额与备用信用

- **字段/单位：**existing_capacity_kw/max_new_capacity_kw；low_temperature_derating；firm_capacity_*；kW；0–1。
- **当前证据：**三原型现有容量与候选量多为示例；S3原型零基建，项目批复不等于其已有资产。
- **进入模型前：**区分原型既有资产和候选建设；按同一低温条件处理出力和可靠容量；优先保证主案例热源上下限。
- **不能据此声称：**不能把设计名义容量当极寒实际容量；不能把候选能力说成已建，不能重复叠加柔性备用。
- **敏感性或验收：**零新增时既有容量可追溯；出力不越上限；极寒最差时段和备用组合独立检查。
- **最小交付：**asset_register.csv + capacity_audit.csv。责任：设备模型角色；验证角色；P0：必要出力和可靠性约束。


### P11 分时电价与客户资格

- **字段/单位：**planning.electricity_price_column；resident_heating_electricity_price；electricity_tariff_scope；元/kWh。
- **当前证据：**固原evidence配置选符合条件居民清洁供暖电价；普通总表应另案。
- **进入模型前：**按北京民用时钟生成峰谷；保存生效日期、用户类别、计量条件；历史天气与2026电价组合明确为规划情景。
- **不能据此声称：**不能声称2021实际电费；不能给所有商业/区域总表套居民优惠。
- **敏感性或验收：**24h峰谷时数及跨午夜边界核验；电量×价逐时独立累加；同服务方案同价格类别。
- **最小交付：**tariff_contract.yaml + tariff_hourly.csv。责任：数据经济角色；P0：调度与经济排序核心。


### P12 电力排放因子

- **字段/单位：**grid_emission_factor；statistical_year/geographical_scope/accounting_scope元数据；kgCO₂/kWh。
- **当前证据：**本地已登记2023全国0.5306；省级因子本轮已核，但不代表已经入模。
- **进入模型前：**按案例核算边界选择全国或省级一套；保存统计年、发布日、地域；冷热碳目标与碳帽共用同一边界。
- **不能据此声称：**不能当逐时边际因子或任意未来年份实际值；不能与生命周期碳足迹因子混用或双扣绿电。

## 当日取舍和放行约束

1. 面积、服务标准、时钟、实际供热驱动温度、初末态与费用/碳边界先完成，不以GIS图表或更多参数情景替代。

3. 原型资本、运维和燃料价的假设不掩盖；避免把异地限价称本地报价。官方因子统计年与电价生效年单独记录。
4. 新接口或年度结果未完成，交付明确的缺口和失败证据。不可用旧结果改名、放宽必要约束或缩短时段来制造已完成状态。
5. 对照的重新规划与固定投资运行压力测试分开标记；不因用户换了室温模型就保留旧成本/碳排结果作为新版成果。

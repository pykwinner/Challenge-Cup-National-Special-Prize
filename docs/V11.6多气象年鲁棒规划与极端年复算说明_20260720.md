# V11.6 多气象年鲁棒规划与极端年复算说明

**版本：** 11.6.0  
**日期：** 2026-07-20  
**范围：** 2020—2024 多气象年数据、联合代表日、同一投资方案跨年审计、极端年 8760/8784 小时正式回放、CHP 弃热与储热互补验收

## 1. 本轮要解决的问题

V11.5 已证明三类场景都能完成“代表期规划—投资冻结—单一年度逐时回放—机器验收”，但规划输入仍来自 2023 一个气象年。单年代表集可能同时低估年际热峰、冷峰、爬坡、最低温和热泵最差工况，属于典型的样本内过拟合风险。

V11.6 将评估口径升级为：对同一城市原型使用 2020—2024 五个连续气象年，先以五年联合代表日决定一次投资，再将完全相同的热源、管网、储热、配电和微网方案逐年审计；容量预审通过后，只对由风险指标选出的极端年份运行完整年度 MILP。该流程把“一个正常年可行”升级为“跨多个真实天气年可解释、可复查”。

## 2. 数据升级与边界

气象数据来自 NASA POWER Hourly API，采用地方太阳时，城市原型为乌鲁木齐、固原和武汉；2020、2024 为 8784 小时闰年，2021—2023 为 8760 小时普通年。15 份逐时气象文件均完成时间连续性、行数、缺失值和数值范围检查。

逐时热/冷负荷仍是由公开气象和规则参数生成的代理，不是城市热表实测。模型结论可用于算法闭环、情景比较和数据需求论证，不能直接替代项目可研。正式参赛定稿仍需用 CMA 站点、热表、建筑、机组、管网和配电实测重新校准。

## 3. 五年联合代表日算法

将五年共 1827 个完整日拼接后，先按室外温度、各节点热/冷负荷、湿度、资源可用率、电价和排放因子聚类；随后强制加入以下锚点日：

1. 系统与每一条负荷序列的最大峰值日；
2. 系统与每一条负荷序列的最大爬坡日；
3. 最低室外温度日；
4. 各可变资源最低可用率日；
5. 经热计量、建筑灵活性等修正后的最大有效负荷日；
6. 每一类热泵的最不利电热比/COP 风险日。

原始出现次数除以气象年数，故代表日权重和等于平均历年长度：

\[
\sum_{d\in D^{rep}} w_d=\frac{366+365+365+365+366}{5}=365.4.
\]

再以五年平均热/冷需求能量为目标，在权重守恒、非负和极端日最低权重约束下执行 SLSQP 受约束最小二乘校准。三场景最终保留 13、12、17 个代表日；跨五年覆盖告警分别由 10、8、4 项降为 0，热峰和最大爬坡捕获率均为 100%，最大能量偏差分别为 0.027%、0.027% 和 0.241%。

## 4. 同一投资方案的跨年压力测试

新增 `prepare_fixed_investment_plan` 与 `replay_prepared_fixed_investment_plan`：代表模型只规划一次，全部候选投资转为固定既有容量，多个年度仅重建运营层。这样避免每个气象年重复规划，也确保跨年比较使用完全相同的资产组合。

快速容量审计同时检查热源备用率、热泵低温折减、储热可靠容量、配电接入、微网本地可靠出力和场景目标映射。初始 2023 单年方案的通过数为 S1 5/5、S2 1/5、S3 4/5；五年联合方案提升为三场景全部 5/5，即 15 个“场景×气象年”组合全部通过。

场景二将配电可靠容量口径从 `all_installed_electric` 改为 `portfolio_dispatch`。原因是生物质、燃气、热泵和电锅炉是互为备用的热源组合，假设所有电热设备同时满发会重复计算备用容量；组合调度口径要求在 15% 热备用率下选出可行峰值热源组合，再计算其最小可靠电力需求，与模型真实调度逻辑一致。

## 6. CHP 弃热与储热物理漏洞修复

场景一存在 CHP 最小电出力约束。原模型没有显式冷凝/旁路弃热通道；当储热充放互斥被连续放松时，优化器会利用往返损耗循环消纳多余热量。V11.6 新增两道防线：

- `chp_heat_rejection`：仅 CHP 源侧可用，受 180 kW 功率上限约束；弃热计入 CHP 容量、热电耦合、燃料成本、碳排放和㶲损失，但不计入有效供热、清洁热或非化石热份额。
- 储热吞吐成本与互补后验门：充、放电量计入泵耗/换热器循环/寿命退化代理成本；年度证书计算每个储热、每个时段的 `min(charge, discharge)`，只要最大同步充放超过数值容差就拒绝认证。

修复后的 S1 2024 回放中，中央水罐最大同步充放功率为 0，状态方程残差为 0，循环边界通过；CHP 年弃热为 800.4 MWh。该数值是公开代理参数下暴露出的工程核查量，不应被描述为真实项目结论。正式项目必须核实机组冷凝/旁路能力、最小发电曲线、弃热环境约束和储热 O&M 成本；若实测不支持 180 kW 弃热上限，应重新规划或恢复更严格的机组启停模型。

## 7. 代码与可维护性提升

- `heatplan.representative`：集中管理服务需求列、聚类特征、模型派生锚点和多年度代表日构建，避免脚本复制算法。
- `heatplan.multiyear`：统一跨年容量审计、风险归一化、极端年份选择和逐年审计产物。
- `multiyear_readiness_cli`：一次规划、五年快速容量审计。
- `multiyear_replay_cli`：一次规划、多极端年正式回放，可用 `--profiles` 局部重跑并保留其他场景汇总。
- `crawl_public_data.py`：支持多年份、闰年 8784 行校验和已有天气复用。
- 机器证书新增 `storage_charge_discharge_complementarity` 门；年度结果新增 `rejected_heat_kwh_per_year`。

全工程自动化回归为 **73 passed**。新增测试覆盖普通年/闰年、固定方案复用、多年度权重守恒与极端捕获、CHP 最小发电下的源侧弃热、储热同步充放拒绝以及原全年回放闭环。

## 9. 阶段结论与下一步

V11.6 已把通用框架从“三场景单年可行”推进到“三场景五年容量审计全通过、七个极端年完整时序认证全通过”。最重要的提升不是增加一个漂亮指标，而是建立了可复现的反过拟合证据链，并在求解提速过程中用新增验收门主动发现、拒绝和修复了储热循环耗散漏洞。

下一阶段应优先做三项工作：用 CMA/热表实测替换代理数据；对代表日数量、弃热上限、储热吞吐成本和热泵低温性能做敏感性/置信区间分析；把多年度天气与燃料、电价、余热可用率联合成概率/分布鲁棒场景，而不是把气象不确定性单独处理。

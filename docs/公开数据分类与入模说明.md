# 三类供热场景公开数据分类与入模说明

## 1. 数据组织原则

本数据包将公开资料分为“直接事实、规划测算、规划目标、示范项目、能效准入、官方排放因子”六种口径。不同城市的数值不能直接拼成一个虚构城市：乌鲁木齐、固原、武汉分别作为三类场景的代表性原型，公共参数单独存放。

截至2026-10-01，本地来源目录实际有67条来源、312条结构化指标；保留三地2023年各8760小时气象，并已有2020—2024扩展资料。这是文件盘点，不代表本轮已重新核实所有旧来源。指标除供热规模外，已扩展到工程投资、燃气与热价、生物质资源与采购、农村清洁取暖补贴、热泵能效和区域能源站设备组合。

公开资料目录位于 `data/public_sources/`：

- `source_catalog.csv`：来源、发布单位、年份、用途和局限；
- `scenario_public_facts.csv`：从政府文件提取的结构化指标及模型字段映射；
- `scenario*_weather_2023.csv`：逐小时气温、湿度、风速、太阳辐射及派生字段；
- `weather_manifest.yaml`：地点、经纬度、文件和行数；
- `crawl_metadata.json`：抓取时间、API请求和缺失值统计。

## 2. 场景一：乌鲁木齐存量集中供热低碳重构

重点使用热电厂供热能力、供热面积、集团管网和换热站规模、燃气锅炉房整合数量、工业余热接入条件及联网扩展面积。建议映射到现有 `scenario1_existing_network.yaml` 的热源既有容量、管线长度、候选联络管、退役边界和政策路径。

补充数据包括乌鲁木齐智慧供热EPC预算及覆盖规模、集中供热天然气价格、转供热价格，以及济南44MW大型电热泵能源站和北安DN1400骨干管网改造案例。这些异地案例适合构造单位造价区间，不宜作为乌鲁木齐项目的单点报价。

供热面积和城市级MW容量不能直接压缩到示例三节点网络。应先选择一个片区或按比例缩放，并保留“每万平方米峰值热负荷”和“每公里骨干管网容量”两个尺度一致性检查。

## 3. 场景二：固原分散供热清洁化转型

固原规划明确区分城区、县城、无集中供热区和一般农村，适合构造分布式热泵、生物质锅炉、气网可达性和小型区域管网候选集。规划热指标可用于峰值负荷校准；村委会锅炉数量、覆盖面积和农村改造户数用于节点聚合。

公开规划没有给出生物质逐月收集量、含水率、采购价、运输半径和道路中断概率。这些字段仍应通过农业统计、企业询价和实地调查补齐，不能把示例供应链参数宣称为政府数据。

新增的固原2024年秸秆统计可计算“可收集量减既有利用量”的保守增量资源上限；政府采购公告提供颗粒燃料热值和最高限价；彭阳实施方案提供炉具与空气源热泵补贴。需要注意，秸秆产生量、可收集量、未利用量和最终可用于供暖的燃料量是四个不同口径。

## 4. 场景三：武汉夏热冬冷高品质新建

武汉区域能源站案例证明空气源热泵主供、燃气冷热电三联供与锅炉备用的多能互补路线；能效指南给出空气源和水地源热泵准入、节能与先进水平，可作为COP情景边界。

初步设计批复进一步给出29.60MW供热能力、8台1583kW空气源热泵、2台7MW燃气锅炉、150kW屋顶光伏和11.23km冷热管网；项目公开资料给出50—55℃冬季供水温度和一期投资，可用于校准第三类场景的设备组合与低温管网尺度。

高品质供热仍缺少公开的逐时占用、住户行为、室温偏好和除霜实测曲线。当前逐小时湿度可用于识别高湿结霜时段，但除霜损失系数必须用厂家试验或实测标定。

## 5. 气象数据使用边界

自动抓取的NASA POWER为公开格点/再分析气象，可作为明确声明的数据情景输入。若能获得适用国家站或NOAA ISD资料，可比较最低温度、湿冷时数和采暖度时等；观测质量和独立留出资料充分时再做偏差校正。CMA产品访问、站点覆盖与权限需核实；主办方数据或站点资料不是当前公开案例继续实施的前置条件。ERA5可作另一气象产品对照，但两套再分析一致不等于当地实测准确。

既有抓取记录使用LST，不可直接贴北京时间。先核对各地点UTC/LST映射，再对齐电价、占用及服务期；新下载乌鲁木齐UTC/LST各48小时样本仅用于时钟核验，未覆盖或替换全年输入。详见[权威来源索引](权威方法与数据来源索引.md)和[参数补齐清单](关键参数补齐清单.md)。

`solar_heat_availability` 是以当地全年太阳辐射95%分位数归一化得到的模型派生字段，不是观测站直接发布的设备可用率。`heating_degree_c` 以18℃为基准，仅用于构建负荷代理，不能替代建筑热负荷计算。

## 6. 推荐入模顺序

1. 用三地逐小时气象替换24小时演示时序并生成保序典型日；
2. 按公开热指标和面积校准峰值负荷；
3. 用公开热源、管网和项目规模约束候选容量；
4. 对未公开的成本、效率和可用率设置低—中—高三档，并做敏感性分析；
5. 所有结论保留 `source_id`，区分事实、目标、测算和模型假设。

复现抓取：

```bash
PYTHONPATH=src python scripts/crawl_public_data.py
```

## 7. 历史8760小时转换与公开数据复算记录

以下为原有流程及历史结果说明，本轮未重新求解。不能据此认定拟议RC、完整季或新统一碳口径已验收；其中82.75 kW建筑可靠信用尤其仍需由实际温度状态证明。历史热㶲指标也不自动等于全系统㶲效率。

`scripts/build_public_scenario_inputs.py` 将三地8760小时气象与已审计的24小时负荷形状结合，以18℃采暖基准生成逐时负荷代理，再通过极端感知聚类压缩为9个代表日。代表日权重之和严格保持365天，最低温、最大负荷和最大爬坡日强制保留；每个代表日拥有独立 `boundary_group`，短期储热和机组状态不会跨不相关的典型日串联。

公开数据复算结果保存在 `outputs/public_data_validation/`：三类场景最坏失供率均为0，火用核算与水力后校核均有效。第一类在公开极端天气和管段N−1下需要新增DN250候选支线；常规转型场景的清洁热占比为75%、余热占比约45.98%、化石热占比约16.91%。第二类进一步使用固原逐时太阳辐射驱动微网出力：清洁热占比约93.72%，外购电约22.14万kWh/年，本地可再生电约46.23万kWh/年，孤网场景外购电为0且零失供；求解时限内相对间隙约1.25%。第三类修正行为冲击重复计量，并加入82.75 kW建筑热惯性可靠削峰信用后，零失供方案由约0.563降至约0.509元/kWh；独立供热边界下仍高于0.40元/kWh目标，需要进一步提高同峰值利用小时、建立冷热/DHW共享资产分摊或采用约30.6%的资本补贴。

第一类年度规划为控制整数规模，采用“投资规划—运行复核”分层：代表日规划暂不展开CHP与锅炉逐时启停，冻结投资后恢复启停与爬坡，对六类场景逐一复演，结果全部可行且零失供。

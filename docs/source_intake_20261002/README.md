## 1. 供暖设计参数已落实到原表

用户提供的[建标库链接](http://m.jianbiaoku.com/webarbs/book/16582/1663708.shtml)属于《民用建筑供暖通风与空气调节设计规范》GB 50736-2012的**条文说明附录A**。城市数值应核对正文表A，其[建标库正文入口](http://www.jianbiaoku.com/webarbs/book/16582/1663640.shtml)已从目录确认。

建标库正文持续显示加载中，因此本次从[中国建筑科学研究院建筑防火研究所刊载的附录A](https://gf.cabr-fire.com/m/article-12078.htm)读取原表图片；有关城市的原图、本地副本与SHA-256见[参数登记文件](../../data/design_parameters_gb50736_2012_verified.json)。不是根据搜索摘要抄录数值。

| 城市 | 原表台站 | 供暖室外计算温度 ℃ | 冬季空调室外计算温度 ℃ | 夏季空调干球/湿球 ℃ | 已有公共场景配置的设计温度 ℃ |
|---|---|---:|---:|---:|---:|
| 乌鲁木齐 | 51463 | -19.7 | -23.7 | 33.5 / 18.2 | -26，继承example_city.yaml |
| 固原 | 53817 | -13.2 | -17.3 | 27.7 / 19.0 | -26，继承example_city.yaml |
| 武汉 | 57494 | -0.3 | -2.6 | 35.2 / 28.4 | -7，来自scenario3_high_quality_newbuild.yaml |

这三列分别服务供暖、冬季空调和夏季空调设计，选择时要与建筑服务定义一致。规范温度与实际寒潮输入承担不同校核任务：先用设计参考工况比较容量，再用同年连续天气和真实寒潮检查保供能力。两者的负荷与容量结果分别报告。

[第4.1节](https://gf.cabr-fire.com/m/article-11766.htm)给出温度的统计定义。表A的三城市统计期均为1971—2000；本工程已有2020—2024气象序列用于近年运行分析。规范给出的5℃/8℃临界温度设计供暖期只作为气候统计参考，当地行政供暖期及项目模拟边界分别登记。

室内设计条件按[第3章](https://gf.cabr-fire.com/m/article-11759.htm)区分气候区、房间用途和舒适等级，再结合实际服务约定确定。围护结构面积、材料、厚度、通风量及热容量仍需建筑图纸或可查建筑原型；这些气象设计参数没有提供某栋建筑的H、C和实测热负荷。

版本适用性还需结合[GB 55015-2021发布公告](https://www.beijing.gov.cn/zhengce/zhengcefagui/qtwj/202204/t20220412_2674410.html)及相关现行通用规范、当地标准审核；公告明确与其不一致的规定以通用规范为准。本次保留“GB 50736-2012设计参考”的准确身份，没有宣称完成所有现行条文或最新地方气象参数审核。

## 5. 对评分与算法亮点的落实顺序

1. **数据依据**：保留源文件、字段与单位、时钟、统计期和哈希。本次已落实规范原图和三城市CSWD档案。
2. **模型合理性**：设计参考温度用于容量校核，连续天气用于动态舒适与储能轨迹；按供暖/冬季空调服务定义选择相应参数。仍需建筑H/C、实际网络和设备参数的独立依据。
3. **算法优势**：在统一服务与相同输入下执行已实现的词典序端点、ε约束扫描、冷热联合优化及固定投资连续回放；新增数据本身不等于这些算法实验已完成。
4. **实验可信度**：先检查三城市新输入与元数据，再完成新求解、基准与消融、连续运行复核，最后更新论文和答辩结果。原已冻结结果不得通过改表直接套用新参数。

天气下载、设计表读取、排放因子核对和建筑资料收集可以并行；数据准入→统一服务工况→优化求解→独立验收→论文/答辩结论应按顺序完成。

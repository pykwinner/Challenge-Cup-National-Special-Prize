# GitHub 工程上传说明

本次将现有 `north_heat_challenge` 工程复制为独立 Git 工作目录，接续目标仓库已有 `main` 历史。原工程未迁移、删除或覆盖。上传的是当前源代码与必要输入，不等同于新增完成了三城工程实验。

## 包含内容

- 当前核心 11.12.0rc1 的全部源代码、脚本、测试与示例。
- 乌鲁木齐、固原、武汉三城市原场景及依赖配置、公开气象输入、多气象年输入、来源登记和设计参考。
- 已选择的数学验证、外部 RC 验证、武汉连续时序原型结果及论文源文件；失败和较差结果同样保留。
- 原始工程 README 备份、方法说明、真实性审计、评分对照及来源资料目录。

`docs/github_upload_20261002/upload_manifest.json` 列出实际纳入的文件、逐文件 SHA256 和本次排除项。清单自身不递归计算自身哈希。`.gitattributes` 禁止自动转换换行符，以保留冻结证据的字节身份。

## 数据的含义

NASA POWER 是公开格点气象产品；Fraunhofer N2 是对应试验建筑的公开观测。两者各自保留出处、处理和许可说明。原三城示例及原型中尚未核实的建筑热工、负荷、费用、设备或网络参数继续保持情景/假设身份，不能据此视为当地实测或形成真实工程改善结论。新增资料没有自动重算或替换历史结果。

## 未上传内容及复现准备

不包含 API 凭据、本地环境、缓存、临时求解输出、旧版本整套工程、重复交付 ZIP、未使用的 CTSM 探索树、CSWD 原始镜像、未确认再分发条件的第三方论文全文及其页面摘录。来源网址和校验值仍保留。N2 已选数据保留其 CC BY-SA 4.0 归属与许可说明。

公开数学验证需先从原发布方取得 GAMS 引用 PDF，校验与预声明实验一致的 SHA256：

```powershell
python scripts/fetch_published_method_source.py
```

该命令使用 HTTPS 下载并严格校验，下载文件不会提交到 Git。也可用 `--local-source <已取得的epscm.pdf路径>` 导入同一原文。未联网取得原文前，依赖该原文身份的两个数学实验生命周期测试不能运行。其它数学求解测试使用仓库内明确列出的公开例题数字。

历史 `C4_published_method/published_lp_01` 的原始 manifest 保持不改；其完整身份校验仍需要原冻结论文 PDF、文本和页面图片。代码仓库未分发这些全文材料，故不能声称在仅克隆仓库后就通过该历史目录的全量校验。重新执行数学实验会生成自己的快照和新 manifest，不覆盖历史结果。

## 上传验证

独立上传目录执行当前测试集：**626 项通过、2 项明确排除**。排除的是 `test_approval_and_first_round_entire_tree_unchanged` 与 `test_final_manifest_hashes_and_approved_identities`，两者依赖未分发的原探索目录整树身份。测试代码原样保留，没有将未运行项计为通过。

测试时使用已经取得且通过 SHA256 校验的 GAMS 原文。一次 Windows 物理 CPU 核数探测警告触发了逻辑核数回退，不影响测试结果。命令见根 README，机器可读报告见本目录对应的 `docs/github_upload_20261002/tests.xml`。

这些检查说明代码在本次环境中通过回归，不代表全部外部资料已获工程参数准入，也不代表三城新版全年和正式多目标扫描均已完成。

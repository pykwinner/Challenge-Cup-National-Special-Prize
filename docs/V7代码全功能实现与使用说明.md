# V7 代码全功能实现与使用说明

## 1. 实现结论

V7 已将《北方城镇供热 V6 政策约束与工程可行性模型说明书》中可由规划、仿真和数据代码实现的功能全部落地。政府批复、热源合同、地质勘察和真实 SCADA 数据本身不能由程序生成，但现在都被建模为必须提供证据的工程准入输入；未通过强制门槛的资产会自动退出优化候选集。

## 3. V7 联合多阶段模型

旧的 `policy_cli.py` 是逐阶段滚动求解，前一阶段决策完成后才看下一阶段，可能产生近视投资。V7 的 `multistage.py` 将各阶段运行子模型合并到同一个 MILP 中，并用建设变量连接累计投运容量：

$$
X_{a,y}=\sum_{\tau:\,\tau+L_a\le y<\tau+L_a+N_a}I_{a,\tau},
$$

其中 $I_{a,\tau}$ 是阶段 $\tau$ 的建设量，$L_a$ 是建设期，$N_a$ 是寿命。最终年份仍有剩余寿命的资产按直线法计算残值并折现。运营成本使用阶段覆盖年份的现值系数，投资成本只在建设阶段发生一次，因此不会重复计算累计容量的资本开支。

阶段热价约束使用所有仍在服役资产的补贴后年化成本，而投资预算只约束当期新增项目。这样同时解决了“累计资产不能消失”和“资本开支不能重复收费”两个问题。

## 4. 工程准入

`example_feasibility.yaml` 对应热源、热网、电网、用户、财务、建设运维六道门。每一项检查包含：

- 是否为强制条件；
- 是否通过；
- 可审计的证据地址或文件编号；
- 关联的热源、储热、管线、配电或末端改造资产。

强制检查失败时，关联资产的最大新增容量或候选管径会自动设为零；若全项目级强制门槛失败，联合多阶段模型拒绝求解。示例中的 `demo://` 证据仅用于运行演示，正式项目必须换成真实文件。

## 5. 财务模型

财务模块逐年计算热费收入、收费率、变动运维、固定运维、所得税、补贴、债务提款、还本付息和残值，分别生成项目现金流和股权现金流。当前示例结果为：

- 项目 IRR：5.64%；
- 股权 IRR：8.82%；
- 项目静态回收期：12.85 年；
- 最低 DSCR：1.153；
- 给定热价：0.230 元/kWh；
- 股权 NPV 为零的盈亏平衡热价：约 0.218 元/kWh。

这些是示例参数结果。正式应用应替换热价、收费率、贷款条件、税率、固定运维和补贴兑现时点。

## 6. 水力热力后校核

MILP 先用线性容量约束选择拓扑，`hydraulics.py` 再使用 Darcy-Weisbach 方程计算选定管段的流速、雷诺数、摩阻、沿程压降和泵功率，并用稳态传热系数估算热损失。超过阈值的管段标记为 `fail`；已建设但常态无流量的联络线标记为 `warning`，要求核实其 N−1 或远期备用价值。

这一层是预可研后校核，不能替代施工图阶段的完整水力网络软件。

## 7. 连续全年与 BTES

`chronology.py` 将带时间戳的小时数据整理为一个连续边界组，使储热 SOC 跨日、跨月传递；不再对每个代表日独立循环。`btes.py` 使用顶部、侧面和底部热损失、储热体热容、充放热效率及温度上下限进行十年筛查，输出长期温度漂移、热损失、未满足取热和 Go/No-Go 结果。

BTES 筛查通过后仍需地质勘察、热响应试验和 TRNSYS/有限元复核。

## 8. MPC 与样本外验证

`mpc.py` 先冻结规划投资，再按滚动窗口重复优化，只实施窗口前端控制量，并将储热 SOC 传递到下一窗口。`validation.py` 使用相关随机扰动同时改变气温、负荷、余热可用率、电价和电网排放因子，对冻结方案进行未见样本回放。

由此形成：长期规划确定安全边界，MPC 负责短期运行，样本外回放负责验证规划是否过拟合既有场景。

## 9. 推荐执行顺序

```bash
PYTHONPATH=src python -m unittest discover -s tests -v

PYTHONPATH=src python -m heatplan.multistage_cli \
  --config data/example_city.yaml \
  --timeseries data/example_timeseries.csv \
  --scenario-specs data/example_scenario_specs.yaml \
  --policy-pathway data/example_policy_pathway.yaml \
  --feasibility data/example_feasibility.yaml \
  --output outputs/v7_joint_multistage

PYTHONPATH=src python -m heatplan.operations_cli \
  --config data/example_city.yaml \
  --timeseries data/example_timeseries.csv \
  --feasibility data/example_feasibility.yaml \
  --btes-spec data/example_btes.yaml \
  --output outputs/v7_operations
```

## 10. 仍需真实项目完成的工作

代码已经实现相应模型和检查接口，但下列证据不能由算法代替：真实 8760 小时数据、工业企业长期供热协议、电网接入批复、地质勘察、道路施工许可、设备报价、融资条款和住户低温末端试验。缺少这些资料时，程序会提供情景分析或阻断候选资产，但不能宣称项目已经获得行政或施工可行性。

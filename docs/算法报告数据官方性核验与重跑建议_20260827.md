# 算法报告数据官方性核验与重跑建议

## 1. 核验结论

当前模型并非“全部使用官方实测数据”。更准确的表述是：**使用官方或权威公开数据建立城市原型，再经规则化映射生成逐时负荷、资源可用率和设备运行边界**。这套数据适用于算法验证、多方案比较和证据链演示，不能替代城市热表、气象站、机组、管网和配电实测进行项目可研。

## 2. 可确认的官方/权威数据

| 数据类型 | 当前来源 | 核验结论 | 使用边界 |
|---|---|---|---|
| 2020–2024逐时气象 | NASA POWER Hourly API | 权威公开格点数据，抓取URL、坐标、行数和缺失统计已保留 | 不是CMA地面站实测；LST不必然等于法定时区 |
| 城市供热规划、面积、项目容量 | 乌鲁木齐、固原、武汉政府及相关主管部门 | 官方公开文件 | 规划值、批复值和已建成值必须分开 |
| 供暖季时窗 | 地方政府/主管部门或项目运营通知 | 乌鲁木齐4392 h、固厘3984 h、武汉2880 h已形成机器可读范围 | 武汉为武昌热电项目服务周期，不是全市法定供暖季 |
| 2023电力平均CO₂因子 | 生态环境部、国家统计局 | 新疆0.6021、宁夏0.6187、湖北0.4044 kgCO₂/kWh | 年度平均因子，不表示真实逐时边际排放 |
| 热泵能效与准入 | GB 19577—2024及地方能效指南 | 可用于COP范围和情景边界 | 不能替代具体机型的低温/除霜试验曲线 |

## 3. 属于模型派生而非官方实测的数据

- 逐时热/冷负荷：由气象、18℃采暖度时和已审计日形状生成。
- `solar_heat_availability`：由太阳辐照分位数归一化，不是设备实测可用率。
- 余热可用率、可再生功率上限、CHP最小电出力：参照公开项目尺度后的原型映射。
- 代表日、权重、最差COP锚点和负荷爬坡锚点：由算法生成。
- 投资、调度、成本、碳排放和失供率：模型输出，不是城市统计事实。

## 4. 属于情景假设或待本地调研的参数

- 设备CAPEX/OPEX、寿命、折现率和残值；
- 余热逐时衰减、生物质运输半径/含水率/中断概率；
- 用户占用、舒适温度、建筑热容和需求响应意愿；
- 分时电价曲线、碳价和未来价格扰动；
- 热泵低温和高湿除霜折减。

## 5. 发现的关键口径问题

现有 `public_scenario_inputs/*full_year_2023.csv` 中 `grid_emission_factor` 是0.44–0.62 kgCO₂/kWh的早期情景化逐时曲线，并非生态环境部发布的2023省级平均因子。因此：

1. 现有算法收敛、零失供和性能结论仍然有效；
2. 绝对碳排放量不应标注为“按最新官方因子核算”；
3. 已新增 `data/grid_emission_factors_2023_official.json`，作为新一轮正式重跑输入；
4. 替换后必须重新求解、计算碳指标并生成新证书，不能直接修改旧CSV的结果列。

## 6. 建议的重跑顺序

1. 用CMA附近站点数据对NASA POWER的月均温度、最低温、湿冷时数和辐照进行偏差校正；
2. 用新疆、宁夏、湖北2023年官方电力排放因子重建输入；
3. 按乌鲁木齐4392 h、固原3984 h、武汉2880 h切取正式供暖季；
4. 重新生成代表日、优化投资、冻结并回放；
5. 对负荷、余热、COP、电价和生物质价格做联合扰动；
6. 更新研究报告的碳排放、经济性和证书编号。

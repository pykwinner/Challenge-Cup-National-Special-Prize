# 代表日核心改进与验证

2026-10-02，本轮直接修改原工程 `src/heatplan/scenarios.py`、`src/heatplan/representative.py`、`src/heatplan/chronology.py`、`src/heatplan/chronology_cli.py`，修改前源码以相应 `*_before.py` 保存在本目录，不覆盖既有实验。

## 1. 真实相邻小时的极端事件筛选

原实现先将负荷排成日×24小时，再在每行内部做差，遗漏23:00到次日00:00的变化。新实现对展平后的序列计算绝对差，但只有时差恰好1小时且处于同一 scenario、boundary_group、source_weather_year 的边才准入。source_time、timestamp、time 按此顺序寻找真实时标；旧不透明模型键只沿用日内位置关系，并返回识别模式。

对系统总负荷和各负荷序列，最大有效变化所在边的两端实际日均选入。若两端在同一天，只保留一次。新增日从所属原聚类样本日的权重中扣除1，总代表天数保持不变。相同最大值以源序列最先出现者确定，未改成保留全部并列极值。

日块内部有缺小时、重复时标、逆序或跨情景即报错；完整日之间可以有缺日期，但不跨缺口计算爬坡。不把整数模型键解析成纪元纳秒。此操作保留极端事件信息；代表日仍需下游模型建立真实跨日约束，或在连续回放中检验。它本身不产生季节储能状态联系。

## 2. 重复日型的稳定聚类

方法仍是 StandardScaler + KMeans(n_init=20) + 簇内最接近质心的实际日。代码现在明确该方法不是独立求解的成对距离 k-medoids。若特征日型少于请求聚类数，采用实际可用的不同日型数，并再次按真实非空标签整理索引。返回的数量和权重反映实际结果，不复制同一天填预算。空输入、空特征、非法K和非有限值明确拒绝。

## 3. 软能量拟合的数值检查

设 A 的每列为一个代表日对各服务能量的贡献，b 为原时序目标能量，w0为原日权重，s=max(|b|,1)，r=max(w0,1)。现有目标是

`min mean(((Aw-b)/s)^2) + λ mean(((w-w0)/r)^2)`，约束 `sum(w)=sum(w0)`、普通日和极端日各有权重下界。

这是带线性约束的凸二次目标，能量是软拟合；即便某项精确匹配不可行，也可能正常求得最小偏差解。正则项还可能在精确匹配可行时保留非零残差。不得把求解成功解释为严格能量相等。

本轮补入解析梯度与等式Jacobian、可行初值、求解后的守恒和下界复核，并阻止 pandas.sum 默默忽略NaN。控制参数非有限、负权重或缺失日标识也拒绝。返回摘要显式登记软拟合性质、守恒残差、下界违背量和原/新能量偏差。

## 4. 多气象年接口

给模型用的唯一键和实际source_time分开保存，真实时间优先使用timestamp。24小时代表日接口明确要求1小时步长。保留供短例诊断使用的部分年度接口，但不再在函数说明中把行数为24倍数等同于完整年；完整年度声明必须另经chronology日历检查。

独立审查IR-001进一步发现：旧实现将真实时间加年份前缀后传给RC模型，导致合法UTC输入也报错。现改为先逐年在原真实轨迹上计算有效负荷/COP锚点，再生成聚类标签；RC输出恢复真实time并将标签另存representative_time_id，确保每个日状态块内部仍连续。测试实际走过RC输入验证与HeatPlanningModel.build。权重目标仍为外生参考列，摘要明确不是内生RC交付热量。

## 5. 覆盖审计与旧CLI步长

独立审查IR-002的反例证明旧coverage helper会将2020和2022的两段平稳负荷拼成100的假爬坡。现对原行序相邻边同时核对真实步长、情景、状态组、来源年和代表日；不把groupby后重新拼接的行当相邻。真实观测边与模型周期首尾闭合边分开，后者不会被报告成观测爬坡。

IR-003涉及旧chronology CLI：原准备函数只检查步长恒定，2小时数据可能被按配置1小时使用。准备函数新增可选expected_step_hours，CLI显式传配置值；1h/dt1及2h/dt2接受，2h/dt1拒绝。通用旧helper未传该参数时仍保留兼容接口，正式全年preflight原有的严格质量门也保留。

## 验证与来源

新增测试 `tests/test_representative_boundaries.py` 使用明确标记的人工反例，验证午夜、缺口、情景/状态/年份边界、重复日型、缺测拒绝、时间列优先级和可独立解析的权重解。它们是程序测试，不是实验观测。

2026-10-02扩展集中验证：新边界测试加原代表日、多气象年及smoke测试共58项通过，1项joblib物理核数查询警告；`focused_tests.xml`记录该运行。随后完成[主工程全回归](../full_regression.xml)：669项通过、可选空间模块因基础环境缺pyproj而跳过；加载隔离依赖后[空间模块23项](../spatial_optional_tests.xml)也通过。上述58项已包含在全回归中，不重复计数。独立审查已复核IR-001/002/003的修复及实际外部计量指标，详见[总报告](../RESULTS.md)。

方法依据：[Teichgraeber等极端事件研究](https://arxiv.org/abs/2002.03059)、[2022时序聚合综述](https://optimization-online.org/wp-content/uploads/2022/01/8753.pdf)、[Kotzur等季节状态联系](https://arxiv.org/abs/1710.07593)。前两篇支持极端信息与完整时序验证的重要性；此处时标准入、重复聚类处理及解析梯度是针对本工程的实现修正，不宣称复现其全部方法。

## 模型复杂度的后续取舍

[IEA EBC Annex58 ST4b报告](https://www.iea-ebc.org/Data/publications/EBC_Annex_58_Final_Report_ST4b.pdf)第20–22页讨论室温观测、热输入及逐步增阶验证。结合本项目已有1R1C精确离散实现，优先增加多步回放、残差与参数可辨识性检查；BDG2缺少室温观测，当前不能用它唯一标定建筑热阻和热容。2R2C宜先在具备相应观测的独立建筑实验上与1R1C比较，再决定是否合入三城模型。扩充状态数本身不是优势证明。

[Bacher和Madsen（2011）](https://orbit.dtu.dk/en/publications/identifying-suitable-models-for-the-heat-dynamics-of-buildings/)给出建筑热动力学模型选择研究的正式出处（DOI:10.1016/j.enbuild.2011.02.005）；本轮已核对机构书目信息，但作者稿抓取失败，未将未读正文公式写成已实施方法。

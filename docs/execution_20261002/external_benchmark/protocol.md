# BDG2 外部计量代表日基准：预注册协议 v1

本协议先于算法运行冻结。输入、质量筛选、实际日预算、指标和失败处理均不按算法结果调整。此实验检验外部计量序列的代表日压缩特性，并提供独立的负荷容量欠覆盖数学诊断；不识别 RC 参数，不评价预测精度，不代替 HeatPlanningModel 运行，不证明中国三城实测或工程节能。

## 来源与样本锁定

- 使用已独立核验的 BDG2 官方固定版本 `9b97ccbe90096aff42ed4fd6493bf7ae692d7118` 的本地 cleaned CSV、metadata、weather；不重清洗、不填补、不修改源文件。来源证据见 `docs/source_intake_20261002/datasets_batch_03/bdg2_sources/`。每个相关 CSV 的实际 SHA-256 必须再次匹配既有审计，LFS 指针不是 CSV 内容。
- 固定类别顺序 hotwater、steam、chilledwater，每类目标 4 个通道，总计 12。按站点 ID、建筑 ID 的字典序遍历，优先每个站点一个通道，建筑 ID 跨类别不重复。若不足四站点，按同样站点顺序进行第二轮；不足目标则明确短缺，不放宽门槛。
- 2016 候选条件：全年有限计量覆盖率 ≥95%，计量与有限室外温度联合覆盖率 ≥95%，负计量值为零，至少一个正值，metadata 建筑面积有限且 >0。排序仅使用稳定 ID，不以能量、峰值、爬坡或算法结果排序。
- 2017 准入只检查有限计量和温度联合覆盖均 ≥95%、无负计量值；不检查能量、正值数量、峰值、算法表现。按已固定的 2016 候选顺序寻找准入通道，保存所有质量拒绝及建筑去重记录。名单在运行算法前冻结。
- 两年分别压缩当年完整日。2017 是同一固定方案的另一年度压缩检查，不能称留出预测。质量筛选样本不代表全部建筑或站点。

## 时标、单位、缺测和范围

BDG2 热计量原值为每小时 kWh，`load_kw = energy_kwh / 1 hour` 为该小时平均 kW，两者数值相同；不称瞬时功率，不再次按论文示例换算。温度为 °C。使用来源的本地标准时间标签，不推测 UTC/DST。

每年重建完整日历用于覆盖报告，保留原始小时计量、原温度和实际日期。一个保留日必须正好有本地 00–23 点 24 个唯一连续小时，计量有限且非负、温度有限。任一小时缺失则整个日退出压缩；合法零值保留，NaN 不变成零。保存所有退出日期及原因。输出分别报告全年观测计量、温度、联合覆盖，完整日覆盖，以及所有有效小时峰值与保留范围峰值，防止筛选隐藏峰值。

算法输入按实际日期排列，不重新编号日期，不把缺口两侧连为相邻小时。输入的 scenario、boundary_group、source_weather_year 在同一观测年度保持一致；仅时间差恰好 1h 的边可以跨午夜，年份和缺日缺口不连接。

## 方法、版本和公平预算

固定特征 `load_kw,outdoor_temp`，需求列 `load_kw`，随机种子 42，基础 K=6，沿用 core 的 StandardScaler 与 KMeans(n_init=20)。普通方法是簇内最接近标准化质心的实际日，并非严格成对距离 k-medoids。

1. legacy：只通过 importlib 加载已保存 `algorithm/scenarios_before.py`，冻结其内容 hash 后运行 extreme_aware，得到实际正权重唯一日数 M。
2. 普通 baseline 使用同一 legacy 接口和 `n_clusters=M`，匹配该例 extreme_aware 的实际日预算。若重复日型导致失败或实际 M 不符，如实记录，不复制日、不悄悄降 K。
3. new_core：待主执行者完成修订，另存不可变源码快照、记录 SHA-256 后，按相同方法重新运行。new_core 自己的 ordinary baseline 按它实际 M 匹配。不同版本 M 不同的直接比较必须标注预算不同，不能把后续 live core 称 legacy。
4. 仅 new_core 增加一次预注册权重消融：对它已选 extreme_aware 实际日调用 `calibrate_representative_day_weights(match_columns=['load_kw'], regularization=1e-4, minimum_extreme_weight=1.0, minimum_day_weight=1e-6)`。固定选日 M，仅改变权重；保持总天数和极端下界。分别记录校准调用耗时、优化残差/下界、能量偏差与 W1，包括 W1 恶化或失败；不调参，不用校准后表现选样。校准只用本年保留范围的同一观测量，仍非预测或独立优化验证。

每法独立计时，控制数值线程为 1，使用 perf_counter，固定种子运行三次，报告各次原始秒数和中位数。每次所选日期、权重须一致，否则失败。I/O 与指标计时另列。失败保留类型、文本、实际阶段、预算，不能从汇总中消失。权重必须有限、非负，正权重实际日唯一，权重总和等于保留日数。

## 固定指标

所有压缩指标参照同一保留完整日范围；全年不完整观测量单列，不外推为全年真实能量。

- 保留范围能量偏差：`(Σd wd Σh qdh − Σretained qt)/Σretained qt`，保存符号和绝对值。
- 峰值保留率：代表小时峰值/保留小时峰值；保存两种参考范围峰值、原峰值退出标记、最大峰值日是否选中。
- 冷日集合按日均温升序、日期升序固定取 `ceil(0.05N)` 日；热日同理降序。报告两者实际日命中率。另报告代表最低温减参考最低温的 °C 差及绝对最低温日命中。冷水的热日指标有物理解释，冷日指标仅为一致的外部温度覆盖检查。
- 爬坡使用原始保留小时上真实时间差 1h 的 `abs(Δload_kw)/1h`，包括午夜；事件集合为正爬坡按大小降序、时间升序的前 `ceil(0.01 × 正爬坡事件数)` 个。命中要求两个端点的原始日期都被选择。报告事件覆盖、最大真实爬坡保留率、最大事件两侧日命中和午夜事件覆盖；不能从代表日拼接序列制造爬坡。
- “两端日均被选中”只证明原始事件信息被保留，不证明规划模型内存在跨日状态/爬坡连接，也不保证运行可行性。独立日状态闭合不能据此称跨日约束完成。
- 持续曲线偏差：参考小时等权、代表小时按日权重，精确加权 Wasserstein-1 距离，除以参考平均负荷。该指标无时间顺序，不能解释为逐小时预测误差。
- 无储能、无损的 capacity-only 辅助参考：`K = max(代表小时load_kw)`；在同一保留原始小时计算 `max(load_kw-K,0)` 的小时数、小时率、欠覆盖 kWh 和欠覆盖能量率。这只是峰值容量充分性下界诊断，未引入设备、成本、储能、控制、可靠性或 HeatPlan 优化结果。
- 压缩：保存 N、M、24M、权重和、N/M、M/N。能量或负荷均值为零、无正爬坡等无定义指标为 JSON null，并保存原因，不静默设为零。

## 冻结、检验与交付

`protocol_lock.json` 保存本协议、脚本、测试、选择清单、环境和相关原始 CSV 的 hash；每个方法版本另保存 version_lock。运行前重新验证锁和输入，运行后核对源码快照未改变。固定环境 Python、numpy、pandas、scipy、sklearn、threadpoolctl、平台及线程设置；本工作工程未证实为 Git 仓库，仅报告内容 SHA，不虚构 commit。

新增适配器 tests 覆盖：真实午夜与缺日；NaN 整日退出；乱序/重复时间拒绝；重复日型失败或预算退化显式记录；已知权重的零能量/W1偏差；被完整日筛选排除的原峰值；候选排序稳定及 2017 负荷表现不参与选样。输出 protocol/status/selection/environment、每例质量和退出日、实际代表日与权重、JSON/CSV 全部指标和失败、配对汇总、findings 与 limitations；运行命令可复用。原 papers 和历史审计不改，GitHub 不上传。

# 三城真实空间参考案例协议

登记日期：2026-10-02（Asia/Shanghai）。本批次只构造真实空间参考连接/候选路线，不构造或优化实际热管网。原datasets/osm CSV、既有审核证据、spatial_quality.py、model.py只读；不上传GitHub。

本批次独占新增文件：`src/heatplan/osm_reference.py`、`scripts/build_osm_reference_cases.py`、`tests/test_osm_reference.py`及`docs/execution_20261002/spatial_reference/`内产物。现有其他文件不编辑。

## 预先固定选择规则

三城分别使用固原中心（106.2420,36.0090）、乌鲁木齐中心（87.6170,43.8250）、武汉中心（114.3000,30.5900）作为明确的参考窗口中心，不把该坐标称作热源。各取中心1.5km半径内的原始建筑质心和道路；城市边界以所给boundary文件核查，另标明该边界未获官方身份认证，乌鲁木齐窗口与更宽行政边界及此前供热规划范围区别。

建筑必须有合法way ID、有限坐标、正占地，质心位于窗口和所给边界。允许标签固定为住宅/办公/学校/大学/医院/商业/零售/公共建筑/宿舍/酒店以及generic yes，但yes明确为用途未确认参考点；排除dam、roof、tank/storage_tank、ruins、construction、greenhouse等全部不在允许集合内类型。按距固定中心升序、再按OSM ID字典序，选前6个（少于6个时如实交付）。选择过程只依据空间/标签，不因路线成功改变对象。floor/height估算不输入热负荷。

道路允许固定现状候选类型residential、service、living_street、unclassified、tertiary、secondary、primary及其link；排除motorway/trunk、proposed、construction、steps、corridor、raceway等。这只筛选参考走廊，不表示获开挖许可。选择相交窗口的整段WKT并保留所有中间顶点，计算时严格报告边界外部分。记录全部采用的对象ID和选区配置，后续重跑使用冻结selection.json。

为限定原始拓扑补取范围，实际小案例采用六个已选建筑质心的凸包外扩400m的候选走廊，取与该走廊相交的上述允许道路way；1.5km窗口其余道路只作背景。走廊由预先固定建筑对象计算，不因路线成功与否调整。此细化在对象冻结和路由前登记。官方API批量每100个way、500个node，单请求最多3次有间隔尝试；只读GET，记录每次失败，失败不扩大范围。原CSV仍只读；当前API快照与原CSV导出时刻未知分别标识，若几何不符仅使用完整新版本或明确回退，不把新refs挂到旧几何上。

## 拓扑、距离和失败规则

优先通过官方OSM API按有限way ID批量补原始node refs、完整几何和layer/bridge/tunnel/access标签，保存请求URL、UTC时间、HTTP状态、原响应和SHA256，不重下整城。补取失败的way保留审计状态。最多3次有间隔的请求，不扩大窗口以追求成功。

有原始refs时按OSM node ID连接，并对layer/bridge/tunnel/access显式判别；不在仅仅几何交叉处生成连接。不把坐标相同但node ID不同视作同一节点。metadata不全时交付清楚标为“几何参考拓扑”的备用案例：只有同坐标、同可知层级的顶点连接，不自动切几何交叉，不能证明道路工程可达。oneway用于车辆交通，不作为热管路径方向要求；本案例为无向走廊候选，其用途单列。

使用固定中心所属WGS84 UTM分区（固原EPSG:32648、乌鲁木齐32645、武汉32650），强制lon/lat轴序，保留lon/lat和easting/northing_m；与WGS84椭球测地线逐段比较并记录最大绝对/相对偏差和窗口外最大半径。仅适用于限定局部窗口，不把经纬度当米，不宣称法定测绘精度。此处在选择/执行前细化了原先允许的米制方法，未改变选区和对象排序规则。

原始node refs存在时，不同layer的二维交叉无共享node不连接；确有共享OSM端节点的桥头过渡允许连接并单列。不同层级在双方内部共同node的异常冲突隔离并报告，不把桥梁端部连通与无交点的跨层相交混为一谈。

建筑吸附到最近允许道路线段内部，最大允许距离150m。超过阈值如实失败；相同线段多个吸附点按沿段参数排序拆分，保留原段长度且不丢失中间点。选择首个建筑作纯参考锚点（不是热站/热源）；分别计算锚点至其余建筑的道路连接最短路线，分列两端连接段、走廊长度、总长度和建筑间直线距离/绕行比。没有路线、超距、缺几何、未知访问条件均记录，不改变对象绕开失败。

## 交付与验收

交付3个案例、selection与原始hash/请求证据、逐节点与候选边的接口数据、准入报告、连通性和路由失败表、距离误差表、3张PNG/PDF地图、可重跑脚本和focused tests。必须检查中间路口连接、跨层交叉隔离、多个吸附点同段、150m阈值、失联失败、路线长度守恒及投影独立误差。原24CSV和旧审核文件hash前后不变；不运行MILP、不注入负荷/容量/COP/投资，待填字段保持null并说明接入前所需资料。

模型接口只输出空间参考node/edge/path和来源，不冒充当前正式HeatPlan源网荷储配置；给出需要再映射的节点、管线及单位，实际物理参数和权利条件未齐时不能进入工程认证。

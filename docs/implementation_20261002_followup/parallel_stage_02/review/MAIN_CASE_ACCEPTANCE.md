## 3. 有自由投资的四行表及小前沿

先准入至少一个能改变方案的设备/容量/连接选择及相应物理、性能、资本和O&M依据。候选容量界应真实构模为自由，允许最优解新增0；不能强迫购置设备来制造投资成果。有0成本理想源或未知报价的支路不能因方便就进入完整财务比较。

| 行 | 定义 | 求解/评价范围 |
|---|---|---|
| 同服务基准 | 事前声明的常规技术/运行限制，保持同一建筑、天气、舒适、服务和经济边界 | 基准限制与资产是否固定明确，不能降低服务换成本 |
| 低成本 | `min Ctech`，再最小排放处理平局 | 联合投资及运行，保留两阶段状态和主目标容差 |
| 低碳 | `min Etotal`，再最小技术成本处理平局 | 同一完整候选可行域和统一冷热/共享电力碳账 |
| 折中 | 从预声明ε扫描的合格非支配候选中按事前规则选择 | 若采用归一理想点距离，明确规则；不称膝点或整条Pareto已穷尽 |

每行至少列：run_id及身份、服务hash、投资范围/自由变量数与投资指纹、CAPEX、年化资本、评价期能源/O&M、基本/需量费用、补贴、另列政策碳费用、技术成本、峰值电力、实际碳、交付冷热量、失供及逐楼越界、状态合规、求解状态/同目标上下界/gap/时间和独立审计状态。相同方案/重复点允许存在；不得凑四个不同方案。没有合格折中则保留空值与原因。

小前沿复用现有词典序及ε入口，先两个端点与少量预声明碳帽，分别保留所有失败和去重结果；不重写算法。每个独特资产计划冻结后在原完整时序检验，运行仍满足同一服务及相应碳帽。联合投资点与固定资产回放点分别标识；未通过连续回放的代表期点不能画成完整时序合格前沿。各点全部构模/端点阶段/ε/回放/审计成本计入预算。

经济闸门：

- 未知费用标`unknown`并说明影响；只有已证明不发生/适用排除/明确理想化参考时才为0。必须项不闭合时报告有限成本范围，或预声明有依据的区间/盈亏平衡敏感性，不报完整财务最优。
- 技术成本清除碳政策与偏好惩罚或按明确边界分列；补贴前技术资本与补贴后业主现金区分。不得求解后删掉惩罚数值就把方案称纯技术成本最优。
- 供暖季OPEX不直接伪装全年OPEX；年化资本可以由已准入寿命/折现率计算，但年度综合成本还需对应年度服务/O&M范围，冷热年度与地源/跨季资源按实际边界补验。
- 没有可追溯收入/收费/经营期/税费依据时，不报项目实际ROI/回收期；可报成本、所需盈亏平衡热价或可承受CAPEX，并明确范围和方程。优化差额是模型比较，不称现场收益已实现。

## 4. 真正多尺度消融的最低证据

需至少两个异质楼宇/节点，有共用网络或资源约束；只有层级名称、OSM共段和汇总表不足。几何共段只有接入容量、损失、泵耗及费用等适用物理字段准入后，才可进入所声明的工程评价。

首轮只做可定位的两方向干预，参数/限额事前登记：

1. **下层→上层：** 异质逐楼规划与聚合规划对照。两份资产方案最终都在同一原逐楼H/C、舒适与服务模型中验收，报告楼宇冷热/温度、区域流量/峰值、系统容量与费用。不能用平均温度掩盖个别建筑不达标。H/C或舒适场景变化另列为物理/服务敏感性，不冒充同服务节约。
2. **上层→下层：** 共用电力、热源/余热或合法网络容量的松/紧约束对照；导出实际起作用的行、可用容量、绑定/拥塞状态及每楼响应。若全局界不绑定、调度不变，就报告无作用，不能靠画图宣称耦合。

固定资产运行与重规划效应分开。楼宇温度/度时、区域峰值/调度、系统投资/费用三层一起报告，找出哪个约束传递作用。不存在独立district容量行时，不宣称已有片区独立限额；可如实说明逐楼—节点网络—共享系统电力的已实现耦合。

## 6. 便携数值复算与来源新准入分别验收

父对话已安排独立便携复算入口。默认复用原来源审核、strict可选再查所有原件是可行的职责划分；它解决缺原电脑路径/历史附件导致不能复算的问题，不能将处理后文件的hash当作新的数据或工程投资准入。

| 入口模式 | 必須检查 | 输出应明确 | 不证明什么 |
|---|---|---|---|
| 默认，复用原审核 | 原审定记录及其已锁身份；处理后展开配置、完整CSV、字段溯源的SHA与审定版本逐一完全一致；相同案例/账户/服务/单位/推导范围 | `source_review_reused=true`、`source_originals_rechecked=false`；核验范围为已审核处理后输入身份及数值复算；列出原审查身份和未在本次打开的原件 | 本次重新核对原PDF；新增字段准入；设备/报价实测或当地工程真实性 |
| strict，原件重查 | 默认全部要求，再验证所用原PDF/网页缓存/原数据存在与hash及原协议要求的核查项目 | 本次实际重查范围、缺件/失败，不把只核hash写成逐页逐值重新审核 | 未核条款、参数识别或现场校准；新的经济收益结论 |

默认仍须拒绝：新配置或CSV或溯源hash改变、继承/默认值变动、案例对象或价表/服务边界改变、原审定记录不适用/未通过、用新建本地manifest自行批准的输入。此时需新的来源准入，不能“更新hash即可”。strict缺原件应明确失败/未执行；默认成功不能替它补写原件重查通过。

数值复算从已锁输入与导出dispatch/楼宇轨迹重算状态、能量、费用/碳及硬约束；不得只读取原summary的pass。保留源输入身份、计算实现、误差容差和本次输出manifest。处理后参数仍具有原来的实测/设计/标准推导/理想假设身份；SHA完全一致只保证复算的是同一份已审参考。

这两个闸门应分别输出：①`processed_input_identity_and_numerical_recomputation`；②`source_admission_or_reused_source_review`；另有独立的③`free_investment_and_economic_case_admission`。现有理想固定资产参考即使前两项通过，也不自动通过第三项。没有储能仍不伪造SOC，未知费用/收入仍不记0或制造ROI。

本审查至此给出入口合同，未执行或认证尚在实现的新便携入口；由父对话在其最终文件快照上核验。旧冻结脚本保持原身份，不将新入口的有限检查替换旧协议中的strict要求。

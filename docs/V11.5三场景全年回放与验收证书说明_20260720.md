# V11.5三场景全年回放与验收证书说明

**版本：** 11.5.0  
**日期：** 2026-07-20  
**范围：** 三类场景固定投资8760小时回放、批量编排、储热边界后检查与机器可读验收

## 1. 本轮目标

V11.4已经完成代表日极端锚点、受约束权重校准和武汉全年闭环，但另外两类场景仍只有年度数据预检和代表期投资稳定性证据。V11.5把验证范围扩展到赛题要求的全部三类场景，并把“求解成功”升级为可审计的多门验收：数据连续性、代表时段覆盖、规划与回放求解状态、投资冻结、可靠容量、失供率、储热边界、供冷、地源年度热平衡和清洁热约束均需分别给出通过证据。

## 2. 代码与算法升级

### 2.1 三场景隔离批量回放

新增`annual_replay_batch_cli.py`，按YAML清单逐场景启动独立进程。这样可释放上一场景的模型与求解器内存，并确保单个场景失败不会丢失其他场景证据。每个场景记录配置、代表时段、年度数据、时间上限、MIP gap和完整命令。

输入文件内容与关键参数共同形成SHA-256运行指纹。仅当指纹一致且既有结果已成功认证时才断点续跑；输入或参数变化会强制重新计算，避免误用旧结果。

### 2.2 全年回放验收证书

新增`annual_replay_acceptance_audit`，输出`annual_replay_acceptance_certificate.json`。通用硬门包括：

1. 连续完整并按公历年对齐的8760/8784小时时序；
2. 代表时段覆盖审计无`review`项；
3. 代表期规划和全年回放求解状态均为0；
4. 全部投资转化为固定既有容量，候选扩建余量为0；
5. 构模前热侧和配电可靠容量审计通过；
6. 全年及最差场景热失供率不超过配置上限；
7. 每个储热边界组满足状态方程和期末库存要求；
8. 配置中的清洁热或非化石热最低份额得到满足。

武汉联合供热供冷模型另外检查全年冷失供率和地源热泵年取热/年排热平衡。因此S1、S2各适用10门，S3适用12门。

### 2.3 储热边界时点修正

模型输出的`storage_soc[t]`表示时段`t`结束后的库存。旧后检查把第一个输出值误当成时段开始状态，直接计算“末值减首值”；若首小时发生充放热，即使循环边界完全闭合也会显示伪漂移。

V11.5在逐时调度中显式输出`boundary_group`。对循环边界，首时段之前的状态取该边界组最后一个时段的状态，并以模型原状态方程重建残差；对固定边界，则按`initial_soc_fraction × 已安装容量`恢复初始参考状态，并单独计算期末最低库存裕度。输出新增：

- `first_period_end_soc_kwh`；
- `soc_balance_residual_kwh`；
- `final_soc_requirement_kwh`与`final_soc_margin_kwh`；
- `boundary_condition_pass`。

S1低温水罐旧口径显示18.909 kWh“漂移”，修正后循环边界漂移为0，状态方程残差仅为−7.1×10⁻¹⁵ kWh，属于浮点误差。

### 2.4 既有结果重认证

新增`annual_replay_certify_cli.py`，可从既有固定投资配置、逐时调度和审计文件重建储热后检查与验收证书，不需要重复求解几十万变量的全年MILP。这一入口也便于今后验收口径升级后对历史算例统一复核。

## 4. 分场景现实解释

### 4.1 S1：保留骨干网并解耦基荷与调峰

全年回放的可靠热容量裕度为1,100 kW，清洁热占比为75.0%，年度零失供。说明工业余热、余热源热泵和分布式热泵可以承担低碳基荷，燃气/既有CHP保留为可靠调峰。该结果支持“保留骨干管网资产、存量替代、调峰解耦”的赛题逻辑，但不代表公开代理容量可直接用于真实城市项目。

### 4.2 S2：分布式供热与配电同步规划

全年固定热源和配电可靠容量均贴边满足，清洁热占比为91.8%，年度零失供。贴边结果强调：分散式热泵与微网方案不能只优化设备投资，必须同时校核极端气象下的配电接入与本地备用；任何负荷或COP校准变化都应重新回放。

### 4.3 S3：供热供冷共用资产与地源平衡

武汉全年热/冷失供率均为0，清洁热占比100%。地源热泵年取热量/年排热量为0.957，位于0.80—1.25约束区间；两座PCM储热循环边界残差均为0。该结果把“按需响应、多能互补、高舒适度”从文字描述落到共用热泵容量、供冷可靠性、配电和地下热平衡的同一模型中。

## 5. 运行入口

```bash
PYTHONPATH=src python -m heatplan.annual_replay_batch_cli \
  --manifest data/public_scenario_inputs/three_scenario_annual_replay_v11_5_manifest.yaml \
  --output outputs/v11_5_three_scenario_annual_replay \
  --planning-time-limit 180 \
  --replay-time-limit 600 \
  --planning-mip-gap 0.005 \
  --replay-mip-gap 0.01
```

结果汇总见`outputs/v11_5_three_scenario_annual_replay/annual_replay_batch_summary.csv/json`；答辩图见`outputs/v11_5_figures/`。

## 6. 验证边界

全工程自动化回归为`68 passed`。代表日模型五次重复构模中位数为：S1 0.0632 s、S2 0.0508 s、S3 0.0446 s；模型结构与V11.4一致，新增开销发生在结果审计与批量编排层，不扩大MILP。

V11.5证明的是：在当前公开天气、规则化负荷代理、设备参数和政策假设下，统一模型对三类场景均能完成“代表时段规划—冻结投资—连续年度回放—多门验收”的软件与算法闭环。公开原型不是项目实测；正式竞赛应以气象站、热表、建筑、设备、管网、配电和价格实测替换代理数据，并保留同一套代表日生成、权重校准、全年回放和验收流程。

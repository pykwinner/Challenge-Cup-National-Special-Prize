## 2. 每次上传的必填记录

| 字段 | 要求 |
|---|---|
| 版本号与状态 | 使用明确版本号，另列正式版/候选版/实验版；核心代码版本与交付批次需要分别记录时分开列出 |
| 上传日期 | 使用实际日期/时间及Asia/Shanghai时区；构建时间、测试时间和上传时间分别保留 |
| 仓库与分支 | 记录目标仓库地址和真实分支名 |
| 完整commit SHA | 记录最终上传且验证过的40位提交；短SHA可用于展示，但不能替代完整身份 |
| 上一上传基线与改动 | 指明上版commit，列出本次算法、模型、数据、配置、文档与依赖的实际变化及重要限制 |
| 测试结果 | 记录命令、运行环境、测试对象、通过/失败/跳过/排除数量、警告及结果文件；没有运行的检查与原因单列 |
| 数据与分发范围 | 记录新增/变换/排除的数据及来源、许可和获取方式，保留凭据和临时文件的排除规则 |
| tag | 里程碑标签必须明确、不重复，准确指向对应commit；尚未创建则写“无”，不得把计划标签写成已有标签 |
| 远端核对 | 上传后实际核对远端分支/tag对应的SHA与本地已验证提交一致，记录核对结果和时间 |
| 交付链接 | 向用户提供版本、状态、提交链接；有tag/release时同时提供相应链接 |

每次更新清楚的CHANGELOG/上传说明，并保留本次机器可读清单和测试记录。测试通过只对应其实际测试对象及范围，不据此扩大为三城真实工程验证或正式论文实验已完成。

## 3. 顺序要求

1. 阅读本文件，确认上一上传基线与原工程最新改动，确定本次纳入和排除的文件。
2. 同步选定内容到本次上传工作目录，核对版本、来源、依赖和文件身份；避免将历史输出误列为新实验。
3. 对实际将提交的代码/数据副本运行所需检查，记录完整命令、结果、未运行和排除项及原因。根据改动选择检查范围，不把历史测试改日期当新测试。
4. 完成版本、状态、变更说明和上传清单。记录对应源树/清单身份，避免在版本说明中出现尚不存在的最终SHA。
5. 形成提交并上传。若之后修改代码、配置或数据，应重新评估相应检查，验证身份绑定到实际发布内容。
6. 对里程碑创建独立、明确的tag；既有标签保留原指向。标签名称包含候选/实验身份时，与版本状态保持一致。
7. 实际读取远端分支/tag指向，核对完整SHA，补记最终提交与核对结果，提供可点击链接。

最终commit SHA在提交完成后写入交接/发布登记；不要求被该commit跟踪的文件同时包含其自身最终SHA。通过提交前的源树/文件清单身份、提交后核对和外部交接记录形成对应关系。

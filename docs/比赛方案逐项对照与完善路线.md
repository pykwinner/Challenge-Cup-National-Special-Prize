# CP-202611 比赛方案逐项对照与完善路线

核查日期：2026 年 10 月 1 日。对象是当前主工程 **11.11.1**，目录名中的 V10 不代表当前代码版本。依据为用户提供的 12 页比赛方案、当前源码、配置、历史计算产物及现有提交材料。页码均为原 PDF 页码。

**结论：继续以 11.11.1 为开发基础是合理的，但现在还不能据此宣称已全面满足比赛要求。** 源网荷储联合优化、风险规划、数值审计和财务核算已有较扎实的工程基础；决定比赛说服力的短板，集中在完整供暖季、建筑真实室温、地理布局、多尺度案例，以及研究报告与实际实现的一致性。继续添加算法名称，不能替代这些证据。

用户已补充明确：**主办方没有可提供的数据，后续以现有工程和现有资料为基础。** 因此不把取得主办方数据作为前置条件，也不因使用公开或代理数据就把已有功能判为没有。核查区分算法功能、已生成结果及现实验证范围；公开来源、派生和假设应如实标注。当前有无清单见同目录《赛题要求与现有工程逐项核查清单》。

原文没有明确规定必须使用主办方或实测数据才能完成案例仿真。本文涉及实测校准、真实资产或现场效果时，指向结论的验证范围，不构成额外参赛门槛。现有公开输入与明确假设可以支撑完整原型仿真；应按实际缺少的功能和结果判定完成度。

本文完成逐项审查和完善设计，不修改业务算法，也不重新运行大型优化。此前 11.11.1 的 248 项测试通过记录仍可作为软件回归证据，但不是完整供暖季、真实建筑舒适度或比赛得分的证明。下文的补法和验收条件属于本项目建议，除明确标注外，不是主办方新增要求。

### 2.3 三类典型场景

**第一类是保留既有资产的低碳重构。** 第 2 页同时强调骨干管网保留、化石能源存量替代、工业余热、跨季节储热、可再生能源和调峰解耦。S1 已有既有管网、锅炉、CHP、余热、热泵、退役与改造选项，方向较吻合。但乌鲁木齐名称对应公开资料参考的原型，不能当作真实城市资产逐项复刻。

公共年度配置关闭了 CHP 和燃气机组的启停约束，相关历史结果不能同时声称已验证完整启停过程；弃热能力等也有假设。现有短时储热不能仅改名称就成为跨季节储热，独立的 BTES 筛选模块也不证明季节储热已进入同一规划和调度闭环。

建议交付一份保留、改造、新增、退役资产表；在同一服务量和舒适条件下比较原系统、余热替代、含储热和可再生协同。若跨季节储热作为核心亮点，必须覆盖非供暖季充热、冬季放热、长期散热、能量容量及初始库存来源。只跑冬季不能证明夏充冬放的经济性。

**第二类是基础设施薄弱条件下的清洁替代。** 第 2 页中的分布式热泵、生物质能或区域微网，不意味着每个方案都必须同时安装所有技术。S2 的分布式设备、电网限制、停电、燃料库存和微网约束已有基础；证据校准配置已经取消无依据的免费既有光伏、电池和备用资产，避免人为偏向某技术。

仍需明确散煤、燃气或混合基准，可以先使用有来源且说明适用范围的典型参数。现有三节点原型不能直接代表“散烧到集约”的住户级事实。当地生物质资源总量不等于可采购供热燃料量，库存、距离、热值、含水率和到场价需注明来源或假设，并检验敏感性。居民清洁取暖电价也不能自动适用于商业或公共建筑总表。应按用户类别比较支出、可靠性和清洁替代效果，而不是只给全系统平均热价。

**第三类是零基建、高间歇、高舒适的新建供热。** S3 既有热源、管网、储热和电网容量设置为零，已有占用、舒适偏差、热泵、地源、太阳能和储热候选，结构上贴合题意。其突出问题是占用与舒适仍为规则参数，只有两个用户区域，缺真实建筑物性和绝对室温证据。

若采用地源冷热联供，还须验证钻孔能力和全年取排热平衡。冬季季节证书不能代替全年验证，冷热共享设备的成本也不能全部分给供热或重复计入供冷。武汉某项目服务期只能作为该案例服务边界，不能称为武汉全市法定供暖期。

第 5 页分别要求结构规范、注释充分及命名规范、封装复用。当前模块和配置分离已具备基础，但模块数量和测试数量不能直接证明三项全部满足。

| 原文要求 | 建议检查方法 |

## 5 第六部分评分所需的关键技术修正

### 5.1 源网荷储模型应怎样说明

当前统一索引覆盖节点、温度等级、热源、管道、储热和时段。热源投资、退役、容量及可选启停，与管径、储热、需求移时和缺热共同进入节点热平衡。这是本项目最值得保留的主线。

但应把它准确称为热功率流规划模型。当前管损采用效率和温度降额，水力模块属于求解后的稳态估算；并未完整联立水量、压差、供回水混合温度及热输运延迟。代码有温度等级，也不意味着已经动态求解供回水温度。

建议为主案例导出可独立重算的能量账本：热源输出、网络进入与流出、热损、储热充放及损耗、用户实际得热和缺热。热泵需同时列出输入电、环境取热和输出热；若做冷热电联供，所有共享设备和计量边界必须唯一，避免重复计入收益或服务量。

### 5.2 完整供暖季是当前最直接的证据缺口

已有 2020 至 2024 年数据。实查三城 2023 和 2024 年输入，合并各为 17544 个连续小时，能够支持构造历史跨年服务期；赛题没有规定必须是 2024 至 2025 年。因此缺 2025 数据不是唯一可走路线的障碍。

但是存在四个必须先解决的问题：

1. **时钟口径。** NASA 来源声明当地太阳时 LST，现有 CSV 没有时区。不能直接附加北京时间标签后认为完成转换。应按供应方时间定义核准，优先取得明确 UTC 数据再转本地时间；所有占用、电价、气象、资源列须使用同一时钟。
2. **服务窗口。** 历史供暖季起止须有对应年份依据；无法核实的，明确写成案例服务期假设。不得把后一年通知机械改年份，当成前一年真实政策。南方案例可定义项目服务期，不能伪装成全市统一法定期。
3. **动态初态。** 三城都带建筑状态，S2 还涉及启停、燃料库存和电池。当前季节入口默认拒绝这些尚未承接真实初值的状态；允许循环假设的开关仅表示披露假设，不能补出季初温度或库存。
4. **同一投资连续运行。** 不能把两个公历年分别优化得到的调度拼接为跨年季；容量、初末库存、建筑状态和约束可能不同。应固定同一规划投资，在一个连续时域求解并审计。

11.11.1 季节入口已有准确时间戳和储热边界校验，当前通过例为 **4 小时人工数据**，只证明接口机制。下一步应补建筑、机组、燃料和电池的显式初态，以及季前预热和充能来源；然后输出每小时调度、末态、热平衡残差和异常清单。

季节验证也不能代替年度验证。当前入口把年度碳帽、地源全年平衡、生物质年供给、年化预算及热价等列为待年度补充，避免用冬季分母假算全年。正式案例应保留“完整季运行证明 + 同投资的必要全年证明”，并把区间量和年度量分开。

### 5.3 负荷预测文字需要先与代码对齐

当前热负荷预处理可概括为：

`Q[n,t] = Q_template[n,h(t)] × clip(max(18 − Tout[t], 0) / max(18 − Tout_template[h(t)], 1), 0, 1.8)`。

其中 18℃ 和 1.8 是当前构造方法中的参数，不能据此宣称全部建筑的真实设计室温或真实极寒峰值。模型还会叠加占用、退温和行为倍率。这个方法可以产生解释清楚的演示时序，但缺少围护结构、换气、太阳及内部得热的实测校准，也没有留出集精度证据；截断上限可能压低极寒峰值，应做敏感性检验。

现有研究报告生成器却写了 UA、通风负荷和绝对室温 RC 方程，还写到 COP 分段线性化。实际 COP 主要由外部温度和固定温级预计算。正式材料必须根据执行路径调整表述，或真正完成相应模型及验证后再使用这些论述。**论文里出现某公式，不等于代码已求解该公式。**

取得建筑与计量数据后，优先采用可校准的一阶或二阶 RC，或温度、时间、建筑类型驱动的统计模型。训练和验证按连续时间划分，避免随机打乱时序造成泄漏。至少报告 MAE、RMSE、峰值偏差、寒潮期间误差及预测区间覆盖；没有真实目标序列时，只报告机制验证和假设敏感性，不虚构预测准确率。

### 5.4 室温模型是必要约束中的核心问题

当前建筑热惯性大致是：

`B[t] = (1 − ρ) B[t−1] + demand_up[t] − demand_down[t]`，并约束 `B` 在热容乘允许温差的范围内。

它表示名义温度轨迹附近的虚拟蓄热偏差。占用时与非占用时的温差限制不同，因而不能说项目完全没有舒适性约束；但它并不直接求绝对室温。状态只在热惯性和需求移时同时启用时创建，并且没有把缺热变量 `unserved` 写入递推。允许缺热时，缺热本身不会直接使该建筑状态降温。

这会造成重要的解释边界：零缺热不等于室温达标，热偏差很小也不证明断热时用户仍舒适；改变 DR 开关也不应让建筑物理约束消失。

建议建立独立于 DR 的绝对室温状态。最小一阶模型为：

`C_b dT_b/dt = H_b(Tout − T_b) + η_b Q_delivered,b + Q_internal,b + Q_solar,b`。

在时段内输入近似不变且 `H_b > 0` 时，可使用精确离散式：

`a_b = exp(−H_b Δt / C_b)`

`T_b,t+1 = a_b T_b,t + (1−a_b) Tout,t + ((1−a_b)/H_b) (η_b Q_delivered,b,t + Q_internal,b,t + Q_solar,b,t)`。

建议单位：`C` 为 kWh/K，`H` 为 kW/K，`Δt` 为 h，`Q` 为 kW。`Q_delivered` 应为真实到户热量对应的功率，缺热必须减少它。若它已经定义为进入室内的有效热，应令末端效率为 1，避免重复扣损。占用时温度上下限从项目服务标准和数据确定，不在此编造统一舒适门槛。

同时要选清楚建模方式：若室温方程已内生决定热需求，不应又用独立固定负荷等式强迫同一份热量，造成重复约束。参考负荷可以用于基准或偏差目标，但必须说明它与室温状态的关系。

最小验收用例应包括断热降温、恢复升温、预热上限、不同围护建筑的差异、关闭 DR 后温度约束仍生效、季初和季末状态。导出每栋逐时温度，并统计：

- 在室欠热度时：`Σ occupancy × max(Tmin − T, 0) × Δt`。
- 在室过热度时：`Σ occupancy × max(T − Tmax, 0) × Δt`。
- 未满足热量、最长连续温度超界时间、最差建筑、恢复到舒适范围所需时间。

预热会让某小时供热高于基准需求，但若保持温度上限并降低后续峰值，就不能直接判为无效过供。过供、欠供和缺热量必须分别定义。

### 5.5 地理信息与多尺度不能停留在示意图

当前坐标主要由绘图函数消费。候选管段容量和费用是输入，改变画图坐标不会自动改变实际投资可行域和输配成本。因此目前更准确的表述是“给定候选拓扑下的设备、管径及连通方案优化”。

建议选择一个数据可获得的小区或区域，输入带坐标系的建筑、候选站址、道路或管廊和不可穿越边界。由允许路径计算距离，生成候选管线、施工费用、热损及服务距离限制；至少保留多个站址或路由供优化选择。水力校核超限后，剔除不可行管径或更新约束再求解，并记录改变了什么。

三城当前合并配置均只有 `plant + district_a + district_b`。应建立建筑 ID 到小区 ID、区域 ID 的映射，保留建筑物性和独立室温，再聚合区级负荷。每一层都按同一物理边界核对：`外部输入 + 本地产热 + 储能放热 = 下游实际得热 + 外送 + 储能充热 + 损耗`；跨区域交换在相邻层对应记账，储能另列含损耗和时间步长的库存递推。缺热作为服务差额统计，不作为真实能量输入。仅增加绘图层级不能证明多尺度耦合。

一个适度的初始示例可以包含一个城市热源、两个区域站及各区域两类建筑。这是开发建议，不是官方数量下限。应比较“总负荷聚合”和“保留建筑差异”时的成本、峰值、舒适及容量差异，证明模型分辨率带来决策价值；随后再报告不同建筑规模下的变量数、运行时间和 gap。

城市响应迟滞、区域灵活设备、用户热惯性应在同一案例中有不同时间响应。初期可采用校准的固定输运延迟或一阶热容近似，不必直接开发完整非线性水力仿真；但要处理延迟队列初值、时域末端在途热量和损耗，避免通过边界凭空产生热量。

### 5.6 多目标必须统一边界和求解质量

当前 ε 约束方法在成本与排放之间生成候选前沿，方法本身适合该问题。发现四个具体问题：

1. 排放目标包含供热和制冷排放，但排放上限及前沿排序使用供热排放；冷热场景的两个目标不在相同边界上。
2. 输出没有显式去重与非支配筛选，不能把所有返回行都称为最优前沿。
3. `recommended_knee` 实际是标准化后距理想点最近，不是曲率意义上的拐点，应准确命名或更换算法。
4. 有可行解时，限时求解也能返回结果；可行、达到设定 gap、全局最优和不可行应分开显示。排放端点还使用小成本权重打破平局，不等同于严格字典序两阶段优化。

建议先统一成本、排放、服务量、可靠性和舒适边界，再求端点、扫上限、过滤支配点。每个点记录状态、gap、对偶界、耗时及数值审计。若用寿命期经济成本配年度排放，必须清楚标注时间口径；更稳妥的是使用可解释的一致年值或同评价期总量。

至少改变热负荷、电价、燃料价、资源可用率和建筑参数，观察方案及可行性是否稳定。不允许通过降低服务量或放宽舒适获得表面上的便宜、低碳。对近优方案，可增加组合差异约束保留数个有工程意义的备选，供规划人员比较。

### 5.7 㶲效率与生命周期需要可审计账本

当前以 `max(0, 1 − T0/T)` 给热量赋品质因子，温度需使用绝对温标。已有指标主要比较用户服务热㶲与热源输出热㶲，尚未完整包含燃料化学㶲、压缩机输入电㶲和环境取热边界。因此宜先命名为热量品质匹配指标，不能直接等同于全系统㶲效率。

进一步完善时，应固定环境基准、设备与系统边界，给燃料、电力、余热、热泵、换热器和终端建立输入输出账本。对同一热服务，可最小化外部㶲输入，或明确分式效率目标的处理；品质损失的价格惩罚不能自行证明已最大化完整系统效率。先用少量手算案例核对高温供低温、热泵提温和余热级联，再做大案例。

经济性方面，11.11.1 已修复此前的多阶段投资登记、现金成本漏项、残值、终期及审计等问题，不应继续把旧缺陷列为未修复。但单阶段统一寿命年值不等于不同设备寿命的完整生命周期现金流，优化目标中的风险和舒适惩罚也不是实际支出。

建议统一评价期，并按设备寿命列初始投资、更新、运维、燃料、电力、碳成本、退役与残值：

`LCC = I0 + Σ_y (Build_y + Energy_y + OM_y + Replacement_y + Decommission_y + Carbon_y)/(1+r)^y − Residual_H/(1+r)^H`。

其中 `Build_y` 只计未包含在初始投资 `I0` 中的后续新增建设，`Replacement_y` 为更新支出，`Decommission_y` 为退役或处置费用；新增、更新与初始投资不可重复，终期残值只抵扣一次。中途资产出售等回收收入也应在发生年份单列，避免与终期残值重复。

再分开工程经济成本、投资者现金流以及优化中的非现金惩罚。现有税费按正 EBITDA 简化计税，未形成完整折旧税盾及亏损结转模型，DSCR 也为简化口径；可以透明披露，不必冒充银行可研。NPV、IRR、回收期须能追溯至逐年现金流；无合理供热收入依据时，不应凭空给出投资回报。

### 5.8 图表与分析如何真正服务评分

原文列举负荷持续曲线、源荷匹配热力图、系统能流图，是示例而非限定三种唯一形式。现有报告已有负荷持续曲线和热源热力图，但热力图主要显示 6 个热源的日均功率，没有负荷或供需残差，作为“源荷匹配”的直接证据不够。架构图与网络示意图也不是实际能流账本。

建议用一组相互对应的图表：

| 图表 | 回答的问题 | 必须保持的口径 |
|---|---|---|
| 实际或脱敏地图与选址管线 | 为什么在这些位置建设，服务哪些建筑 | 坐标、路径、站址和成本来自同一候选集 |
| 全季负荷持续曲线及峰值日 | 负荷形状及容量利用率怎样 | 1h，区分基准与优化后实际服务 |
| 分热源逐时出力与需求叠图 | 供给何时与需求匹配，谁承担峰值 | 同时展示损耗、储能、缺热，不只画热源 |
| 楼宇室温和超界度时热图 | 最差用户是否仍得到服务 | 真实绝对温度或明确限定的代理状态，不能混用 |
| 实际能流图 | 电、燃料、环境热和用户热如何守恒 | 流量可由导出表重算，热泵取热独立标注 |
| 成本碳排非支配前沿 | 低碳需要付出多少成本 | 服务、寿命期、碳边界与求解精度一致 |
| 年度现金流和敏感性 | 投资是否可行，结论对假设是否敏感 | 基准、能源价格、折现率、税费和补贴说明清楚 |

至少比较基准、无储热、无用户柔性、完整协同方案；可再加低碳优先方案。这样比堆很多相似图更能说明各项创新的作用。

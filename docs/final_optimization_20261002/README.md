# 最终研究版本：文献驱动的模型与算法完善

本批在已发布rc5基础上完成四项增量：真实厂家性能表到三城逐时调度的连接、热容与共享资源的独立对照、求解结论证书、实验时间轴登记。推荐作为后续论文和答辩的研究结果基线；正式发布版本、提交身份和实际提交副本测试见发布交接记录。本文件不把研究算例当作已投运工程。

## 1. 新完成的模型和算法成果

### 同型号真实性能表驱动的三城运行优化

TICA样本中的TCAV035BHE、TCAV065BHE共165个制热Q/P工况点，已按原PDF页码和单元格位置核对。Q和P分别插值，COP由Q/P计算；原表空白角、跨型号及越界查询拒绝，不用招标门槛代替性能曲线。原CSV中的型号正确，83/82是每型号点数，不是型号后缀。

本轮先对三个城市分别完成电阻基准、单台035、单台065的连续运行，再对两种固定热泵设备完成费用最小LP。每案均为相同连续2880小时、20–27℃服务边界、初末20℃；设备容量有限。LP保存原始对偶向量，独立重建RC、容量、电平衡、费用，并按原声明容差核对数值对偶残差。

|---|---|---:|---:|
| 乌鲁木齐 | TCAV035BHE×1 | 1.3274% | 798.75 |
| 乌鲁木齐 | TCAV065BHE×1 | 1.1088% | 474.44 |
| 固原 | TCAV035BHE×1 | 1.4526% | 908.06 |

这些数值衡量同资产、同舒适范围下的调度改善。六案电量和固定排放因子核算的碳排均增加，完整差值见[费用、电量及碳排比较表](heatpump/optimization_01/optimization_comparison.csv)。比较使用公开BESTEST600 48m²原型的20份合成复制、真实格点气象、共同条件湖北电价/排放因子、厂家样本及理想部分负荷占空比，属于完美预知的条件运行参考。没有TICA设备报价，因此没有混用FT8套餐价，也未从运行节费推断回收期。实际湿度、化霜和启停损失仍需对应设备试验支持。

完整来源、运行、优化与准入边界见[热泵组交接](heatpump/HANDOFF.json)。

另新增[六案有限LP下界记录](heatpump/optimization_01/native_lp_bound_sidecar.json)：把已编码binary64系数作为有理数，用有限变量边界的拉格朗日公式计算下界，再向下舍入输出。它独立保留于原始数值对偶值之外，证书只针对该费用LP；原始可行解仍按数值容差审核，不据此宣称精确可行上界或现场真实性能。

### 纯热容对照解释多尺度协同的收益与代价

新四案保持建筑热损系数H、天气、设备和温度边界相同，组合B建筑热容C的1倍/4倍与共享电力上限的有/无。这样可以独立判断热容作用，不再把H、C同时改变的差异全部解释成蓄热效果。

| 纯热容比较 | C1费用（元） | C4费用（元） | 费用下降 | 电量变化 |
|---|---:|---:|---:|---:|
| 保留6.4796375 kW共享上限 | 5937.6433 | 5660.9648 | 4.6597% | +335.4598 kWh（+4.1669%） |
| 移除共享上限 | 5918.1406 | 5490.9389 | 7.2185% | +570.3316 kWh（+6.9936%） |

四案各2880小时，求解器均报告status 0、gap 0，覆盖23040个建筑小时。保留共享上限时两案均无越限，约束绑定由125小时增至530小时。无限制方案若按同一容量复查，会分别出现121/229小时越限。这说明建筑灵活性价值取决于系统资源约束，不能把各栋独立最优直接相加当作系统可行方案。

新增解析小时热损账本把电量增加与预热造成的散热联系起来；完整决策向量、逐时RC和约束复核同时保存。结果是条件移峰省费，不能改写为节能减碳。[多尺度组交接](multiscale/HANDOFF.json)

### 结果表直接区分“在哪个问题上最优”

新增可复用分类模块和只读报告，检查rc5的61条真实记录、690个输入身份。分类为22条登记子问题容差证书、38条有限候选主目标证书加选定候选内次目标、1条方法参考。

每条保留问题范围、主次目标、原始上下界、冻结容差、数值审核与来源身份。原始字面界和既有数值容差检查分别列出；没有将gap乘以费用或碳排制造误差区间。旧求解语义及冻结实验保持原样。[结果证据表](solution_evidence/report_final/README.md)

### 时间轴从口头说明变成可检查的身份

登记11份实际输入及5类不同时间身份，校核时区、顺序、重复、遗漏、跨块重叠、区间末端、UTC对应与权重。三城2880小时、72小时管网试验、8个代表日分别呈现；加权核算时长不当作状态连续运行时长。

多尺度新runner已调用时间登记模块；总登记覆盖选定输入，并未声称所有历史CLI已统一改造。[时间轴登记](time_registry/run_final/README.md)

## 3. 文献取舍、推荐路径与验收

本轮[文献核对及设计决策](LITERATURE_AND_DESIGN_DECISIONS.md)解释了为何保留连续时序验证、为何单独处理热容与网络约束，以及为何不直接套用“精确聚合”“高阶模型必然更好”等结论。各分组另列方法原文与实际阅读范围。

后续撰写材料时，主线宜为：建筑服务与温度品位进入源网荷储规划；代表日硬约束校准后连续复算；同型号设备性能支撑逐时运行；有限模式温压反馈纠正工程不可行；热容与共享资源对照解释协同价值。最优性、来源与外部观测验证分别陈述。

分组验收以[热泵](heatpump/HANDOFF.json)、[多尺度](multiscale/HANDOFF.json)、[结果证书](solution_evidence/HANDOFF.json)、[时间登记](time_registry/HANDOFF.json)为准。最终提交副本的环境、测试命令、排除项、远端commit/tag核对由发布记录单列，历史通过数不累计成新一轮测试数。

本批新增性能映射和热泵费用LP是独立研究入口；原核心MILP及既有场景配置没有被静默替换。源文件与复现命令按分组交接冻结，便于后续将已验证模块逐步纳入工程主入口。

# V11.2全年数据准入与代表时段偏差审计说明

> 版本前移说明：V11.3已在本版本的数据准入之后增加双试构模全年规模投影、内存代理、规划/回放运行画像和非自动代表时段修正建议；本文保留为V11.2年度数据门与覆盖审计的历史说明。

**版本：** 11.2.0  
**日期：** 2026-07-20  
**定位：** 在任何8760小时大型求解之前，先证明数据连续、口径完整，并量化代表时段压缩偏差

## 1. 升级结论

V11.2把全年回放从“能读CSV并求解”升级为“先通过数据准入，再允许求解”。核心变化包括：

1. 全年质量审计前移到规划求解之前，错误数据不再消耗求解时间；
2. 正式模式严格要求连续8760或8784小时；
3. 自动识别当前配置真正引用的负荷、气温、源温、资源可用率、电价和碳因子列；
4. 对代表时段与全年数据逐列比较年能量、峰值、最低温、最低可用率和最大爬坡；
5. 新增`--preflight-only`，可在不构建MILP的情况下快速完成审计；
6. 短时序只能通过`--allow-short-horizon`显式放行，并持续标记为软件测试。

## 2. 全年时序质量审计

`chronology_quality_audit`输出：

- 行数、起止时间、配置步长和观测步长；
- 时间戳解析失败、重复和不连续间隔数量；
- 必需列缺失、必需值缺失、非有限值和负荷负值数量；
- 总时长是否为8760/8784小时；
- 是否按自然年对齐；
- `chronology_valid`和问题代码列表。

正式全年允许按自然年或供暖年组织，只要连续覆盖365/366天。因此`is_calendar_year_aligned`是审计信息，不是唯一准入条件。

## 3. 模型引用列自动发现

预检不是简单检查CSV有没有若干固定列，而是根据配置自动收集：

- 节点各温位热负荷；
- 间歇供暖日程、用户行为倍率和情景权重；
- 热源可用率、源温、最小发电和相对湿度；
- 管网低温热损所需室外温度；
- 可再生电力、电网和微网可用率；
- 生物质到货可用率；
- 供冷负荷、电价和电网碳因子。

这避免了“CSV看似完整，但某个低温折减或余热可用率列实际缺失”的延迟失败。

## 4. 代表时段覆盖审计

### 4.1 负荷能量与峰值

对每个原始负荷列计算：

- 代表时段权重折算年能量；
- 连续年度实际能量；
- 年能量相对偏差；
- 峰值捕获率；
- 最大相邻时段爬坡捕获率。

默认提示阈值为：年能量偏差绝对值超过10%、峰值捕获率低于99%、爬坡捕获率低于90%。这些是建模质量提示，不是国家或地方政策阈值。

### 4.2 气象、资源与市场极值

- 气温：代表时段是否遗漏全年最低温；
- 余热/可再生资源：是否遗漏最低可用率；
- 电价和碳因子：是否遗漏最大或最小极值；
- 源温：是否覆盖最不利热泵工况。

审计范围标记为`raw_input_before_behavior_and_schedule_modifiers`，表示这是输入数据层检查；模型求解仍会继续应用占用日程、行为倍率和场景修正。

## 5. 两层状态语义

V11.2不把“数据可运行”和“代表时段没有偏差”混成一个真假值：

- `chronology_ready_for_formal_replay`：全年数据满足连续性、完整性和数值准入；
- `representative_coverage_requires_review`：代表时段存在需要解释的覆盖偏差；
- `preflight_status=ready`：年度数据通过且未发现代表时段告警；
- `preflight_status=ready_with_representative_warnings`：年度数据通过，但代表时段需要复核；
- `preflight_status=short_horizon_only`：只能用于软件测试。

代表时段告警不会阻止全年回放，因为回放本身用于量化压缩误差；但报告必须披露告警及其对投资方案的潜在影响。

## 6. 预检演示结果

项目使用现有24小时示例扩展出一份**合成**8760小时序列，仅验证软件流程，不代表真实城市数据。结果为：

| 项目 | 结果 |
|---|---:|
| 时序行数 | 8760 |
| 时序连续性 | 通过 |
| 完整年度 | 是 |
| 自然年对齐 | 是 |
| 正式回放数据门 | 通过 |
| 需复核代表序列 | 4列 |
| 四个热负荷列峰值捕获率 | 100% |
| 四个热负荷列爬坡捕获率 | 100% |
| 四个热负荷列年能量偏差 | -14.23% |

这一结果说明极端峰值被保留，但原代表日权重低估了合成全年能量。正式项目应重新聚类或校准权重，再比较投资方案是否变化。

## 7. 运行命令

```powershell
$env:PYTHONPATH = "src"
python -m heatplan.annual_replay_cli `
  --config data/example_city.yaml `
  --representative-timeseries data/example_timeseries.csv `
  --annual-timeseries your_hourly_year.csv `
  --output outputs/v11_2_preflight `
  --preflight-only
```

若明确执行短时序软件测试：

```powershell
python -m heatplan.annual_replay_cli `
  --config data/example_city.yaml `
  --representative-timeseries data/example_timeseries.csv `
  --annual-timeseries short_smoke.csv `
  --output outputs/v11_2_short_smoke `
  --preflight-only `
  --allow-short-horizon
```

不提供`--allow-short-horizon`时，短时序会在创建规划模型之前被拒绝。

## 8. 验证

新增测试覆盖：

- 8760小时完整自然年识别；
- 时间缺口、负荷负值和必需值缺失；
- 正式回放对短时序的前置拒绝；
- 显式短时序回放兼容；
- 代表时段遗漏负荷峰值和最低气温的告警；
- 预检不创建规划结果目录。

全工程最终回归结果为`57 passed`。乌鲁木齐、固原和武汉三个公共代表日模型均达到最优，正常及最坏情景失供率均为0，旧核心结果与V11.1保持一致。

216时点公共模型重复5次的构模中位时间为：乌鲁木齐0.0618 s、固原0.0488 s、武汉0.0435 s；变量、整数变量、约束和非零元规模均未增加。预检本身不构建MILP，因此不会改变上述结构规模。

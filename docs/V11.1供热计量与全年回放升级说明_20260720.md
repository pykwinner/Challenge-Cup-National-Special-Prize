# V11.1供热计量与全年回放升级说明

> 版本前移说明：V11.2已在本版本的固定投资回放之前增加全年数据严格准入、模型引用列完整性检查和代表时段覆盖偏差审计；本文保留为V11.1需求侧机制与回放接口的历史说明。

**版本：** 11.1.0  
**日期：** 2026-07-20  
**范围：** 供热计量、需求侧节热、按热收费情景、居民热费可负担性、固定投资连续时序复核

## 1. 阶段结论

V11.1补齐了V11战略对齐报告中两个明确缺口：

1. “推进供热计量改造和按热量收费”不再只是实现缺口，而是可配置、可求解、可审计的需求侧模块；
2. 连续时序不再直接允许重新投资，而是形成“代表时段规划—冻结全部投资—连续全年只运行”的正式复核链。

新增机制保持线性，没有引入覆盖率与负荷的决策变量乘积；未配置计量模块的原有三类场景保持向后兼容。

## 2. 代码层升级

### 2.1 节点级供热计量投资

每个负荷节点可配置：

```yaml
heat_metering:
  existing_coverage_fraction: 0.25
  max_new_coverage_fraction: 0.65
  saving_fraction_at_full_coverage: 0.08
  capex_yuan_per_coverage_fraction: 1200000
```

模型新增连续投资变量`heat_metering_coverage[node]`。设既有覆盖率为$c_n^0$、新增覆盖率为$x_n$、完整覆盖节热率为$\eta_n$，则有效负荷为：

$$
D_{n,t}^{\mathrm{eff}}
=D_{n,t}\left[1-\eta_n(c_n^0+x_n)\right]
$$

由于$D_{n,t}$是输入常数，上式对$x_n$保持线性。代码把新增覆盖率对应的节热项直接加入节点热平衡左端，从而不增加逐时辅助变量。

### 2.2 新KPI与约束

新增输出：

- `heat_metering_coverage_fraction`：按基准热需求加权的计量覆盖率；
- `metered_heat_savings_kwh_per_year`：计量行为响应形成的年节热量；
- `effective_heat_demand_kwh_per_year`：节热后的有效供热需求；
- `indicative_heat_charge_yuan_per_year`：给定收费情景下的指示性热费；
- `average_indicative_household_heat_bill_yuan_per_year`：户均指示性热费。

新增项目级政策字段：

```yaml
policy:
  minimum_heat_metering_coverage_fraction: 0.60
  maximum_average_household_heat_bill_yuan_per_year: 3500
```

收费情景由`heat_tariff`显式给出：

```yaml
heat_tariff:
  variable_tariff_yuan_per_kwh: 0.18
  fixed_charge_yuan_per_household_year: 180
  household_count: 1800
```

国家政策没有规定适用于所有项目的统一覆盖率或热价，因此上述数值不会被系统自动填入，必须使用地方政策、企业收费口径和用户调查校准。

### 2.3 全年固定投资回放

新增`heatplan.annual_replay_cli`：

1. 在代表时段上求解投资与运行；
2. 将新增热源、退役容量、储热、管径、管网改造、末端改造、配电、生物质库存、微网和计量覆盖率转为既有/固定资产；
3. 将所有候选投资上限清零；
4. 保留原可靠性约束，在连续时序上只优化运行；
5. 输出投资冻结审计、KPI偏差、季节储热后校核和逐时调度。

压力测试仍可选择放宽缺供约束以“观测脆弱性”；正式全年回放默认不放宽，二者语义已显式分开。

## 3. 示例结果

`data/v11_heat_metering_demo.yaml`是功能演示配置，不代表任何城市正式参数。对示例代表日求解得到：

| 指标 | 结果 |
|---|---:|
| 求解状态 | 最优 |
| 热计量覆盖率 | 60.00% |
| 计量节热量 | 353,948.4 kWh/年 |
| 基准热需求 | 6,356,700.0 kWh/年 |
| 有效热需求 | 6,002,751.6 kWh/年 |
| 指示性户均热费 | 780.28 元/户·年 |
| 失供率 | 0 |

短时序软件烟雾测试使用168小时合成连续数据，结果显示：

- 代表时段规划与固定投资回放均达到最优；
- 热源、储热、管径、配电和计量改造的候选投资余量全部为0；
- 回放失供率为0；
- 该测试只证明接口与冻结语义正确，不证明跨季节年度可行性。

## 4. 验证范围

新增自动化测试覆盖：

- 最低计量覆盖率是否精确驱动新增投资；
- 节热量是否进入节点热平衡；
- 有效负荷、覆盖率、热费和火用账本是否一致；
- 无效覆盖率边界是否被拒绝；
- 代表时段投资是否转为固定既有资产；
- 连续回放是否禁止新增热源；
- 投资冻结审计是否全部通过。

V11.1仍需用真实城市8760 h数据执行三场景正式回放。当前168小时结果只属于软件烟雾测试。

全工程回归结果为`53 passed`；乌鲁木齐、固原和武汉三个公共代表日模型均达到最优，旧核心指标与V11结果保持一致，三场景计量覆盖率仍为0。这里的0不是功能缺失，而是坚持不在缺少地方计量数据时虚构覆盖率；计量机制通过独立演示配置验证。

216时点公共模型重复5次的构模中位时间分别为0.0614 s、0.0476 s和0.0447 s；变量、约束和非零元规模与V11一致。24时点计量演示相对原示例只增加2个连续变量、2条约束和100个非零元，没有增加逐时辅助变量或整数变量，说明需求侧机制保持了稀疏线性结构。

## 5. 运行命令

计量模块示例：

```powershell
$env:PYTHONPATH = "src"
python -m heatplan.cli `
  --config data/v11_heat_metering_demo.yaml `
  --timeseries data/example_timeseries.csv `
  --output outputs/v11_1_heat_metering_demo
```

固定投资全年回放：

```powershell
$env:PYTHONPATH = "src"
python -m heatplan.annual_replay_cli `
  --config data/example_city.yaml `
  --representative-timeseries data/example_timeseries.csv `
  --annual-timeseries your_hourly_year.csv `
  --output outputs/v11_1_annual_replay `
  --planning-time-limit 180 `
  --replay-time-limit 1800
```

正式结论应确认`annual_replay_summary.json`中的：

```json
{
  "all_investments_frozen": true,
  "is_full_year_horizon": true,
  "comparison_scope": "full_year_chronology"
}
```

## 6. 对十五五战略的提升

国家“十五五”战略画像中的`HEAT_METERING_REFORM`由`implementation_gap`升级为`qualitative_mapping`，对应模型字段、实际覆盖率、节热量和热费均可追溯。但系统仍不输出“符合国家统一覆盖率”之类结论，因为国家文件没有给出单个项目统一阈值。

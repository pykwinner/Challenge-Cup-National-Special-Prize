# E4：独立确认集、精确匹配诊断和权重采用规则

日期：2026-10-02。主工程增量，未上传GitHub。原24案例年度、旧算法和旧验证证据没有覆盖或改写；本目录是另外冻结的确认实验。BDG2为海外公开真实表计基准，不能当中国三城现场供热验证。本轮未写论文/PPT。

## 实际完成与适用边界

新增 `src/heatplan/representative_adoption.py`，沿用现有极端选日和软校准实现，增加两个有明确作用的接口：

- `diagnose_exact_weight_feasibility(M, b, w0, lower_bounds)`：独立标准LP检查 `Mw=b`、`sum(w)=sum(w0)`、`w>=lower`。逐行缩放后求解，再在原单位复算见证；区分可行、不可行与数值/求解失败。可行权重只是见证，不替换软校准候选，不改负荷。
- `assess_weight_candidate(...)`：逐项检查研究门槛，再明确采用或回退；同时审查回退权重，不把“已回退”当“合格”。零目标能量的相对误差不可定义，明确留空和拒绝原因。

新增 `scripts/bdg2_confirmation_benchmark.py`，复用原benchmark的完整日适配、选日调用与统计指标。其代码、测试、数据哈希、样本、环境和算法副本已在首次实验前冻结。没有更换求解器、增加并行或启用加速；保持既有seed 42、线程限制1和3次独立调用。

**统计门槛通过不等于规划可用。** 本轮未运行设备规划、费用/碳排对照、室温、储热或固定投资连续运行回放。原观测范围的“容量缺口”仅为观测负荷超过所选峰值的简化诊断，没有设备、损失、库存或调度模型。

## 预先冻结的研究采用规则

这些阈值是研究选择，不是官方评分要求。详见 [protocol.json](protocol.json)，锁文件SHA256为 `a203caca8c643de7b0fc9b5b1efee86878d317d6f9a0fcbb649d02faaa9eb7c0`。

| 检查 | 冻结阈值/处理 |
|---|---|
| 原始选日和观测 | 候选不得改变所选真实日或原观测 |
| 总天数 | 残差不超过 `1e-8 * max(W,1)` 日 |
| 权重下界 | 普通日 `1e-6`、极端日1；最大下界违反不超过 `1e-8` |
| 各匹配能量 | 最大绝对相对误差不超过0.1%，另有 `1e-12` 指标容差 |
| 分布 | 与同一保留观测、同一归一口径相比，W1不得劣于未校准极端法，容差 `1e-12` |
| 保留范围极值 | 所选原事件峰值及最大真实相邻爬坡保留率均须达到1，容差 `1e-12` |
| 全部有效原表计峰值 | 所选峰值/原有效观测峰值须达到1，容差 `1e-12`；完整日筛选遗漏峰值即不合格 |
| 求解失败/零能量/未定义指标 | 保留失败和原因；回退未校准极端权重，另报回退是否通过 |

没有要求候选采用LP见证，也没有为了通过门槛调小正则项。当前软目标仍是能量拟合与权重位移正则的权衡，成功不能解释为硬能量保证。

## 确认集与筛选损失

9个不同建筑，热水、蒸汽、冷水各3个，每楼仅2017一年。按95%表计及气温联合覆盖、无负计量的预声明质量条件，再按稳定站点/建筑ID和站点轮转选取；原开发建筑全排除，优先原7站之外站点。实际全部来自新站Swan、Cockatoo和Panther。选样未使用任何算法表现；全零记录不会因算法失败而被事后换掉。

同站楼不是独立站点重复，故本次为9栋/3站确认，不能说9个独立站点。所有建筑ID、质量、逐项选取/拒绝和来源身份保存在 [selection.json](selection.json)。使用此前官方LFS核验的源commit `9b97ccbe90096aff42ed4fd6493bf7ae692d7118`；原5份实际使用CSV的字节数和SHA256在 [protocol_lock.json](protocol_lock.json)，运行前后均核验。

完整日筛选保留266—363天，实际代表数量8或9。普通法逐例使用极端法实际正权重日数，因此三种统计方法及采用规则输出在每例的实际日数一致。所有缺测保持缺测；逐日退出原因及未填补原日历见 `cases/<case_id>/2017/`。

有效表计能量因完整日筛选退出的比例为0.3090%—35.0245%，中位数7.2819%；5/9例原有效小时峰值退出。`Swan_unknown_Darrin`所选峰值仅为原观测峰值3.23498%。没有擅自删除该源数据尖峰、填补同日缺测或换楼；该例不满足全部原观测范围的采用门槛。原表计相邻边、峰值、筛选丢失小时与能量及容量诊断在每例 `original_observed_scope_audit.json` 明示。

## 实跑结果

下表是**全部固定9例**的案例中位数，不是挑选已通过2例的有利结果。前三行是候选方法；最后一行包含7例未通过的回退输出，不表示9例全部合格。每年都使用当年完整日观测进行压缩/拟合，是未见建筑/站点的方法确认，不是未知未来预测。

| 方法 | 绝对能量偏差 | 归一W1 | 保留范围峰值 | 最大真实爬坡 |
|---|---:|---:|---:|---:|
| 普通实际日，同实际预算 | 2.01777% | 5.98537% | 78.7365% | 49.3995% |
| 极端事件实际日 | 0.808194% | 6.21365% | 100% | 100% |
| 极端日+软权重候选 | 0.00176093% | 6.00724% | 100% | 100% |
| 采用规则输出（含不合格回退） | 0.135826% | 5.94741% | 100% | 100% |

软校准相对极端法9/9例能量偏差改善，W1在6例改善、3例变差。极端法相对普通法7例能量偏差改善，但W1中位数仍变差。最热5%日覆盖中位数仍为0、最高1%爬坡事件覆盖中位数仅3.92157%，本轮没有增加尾部锚点策略，不能宣称已解决尾部覆盖。

精确能量LP9/9可行，但只有2/9软候选通过全部研究门槛；其余7例全部明确回退，回退也均不通过全部门槛。`Swan_unknown_Allison`软校准成功却仍有5.27081%能量偏差；精确LP可行不代表软正则解会达到0.1%。该例回退极端法的W1为97.09175%，是本规则未解决的明显劣化，保留原结果。

本轮证据支持：极端信息保留、能量软拟合的收益/代价，以及能够拒绝不合格候选的采用诊断。它不支持新通用优化算法、完整年工程可行、费用/减排优势，或中国三城现场验证。固定投资连续回放与事件上下文/长期状态联系仍需依赖正式物理案例；不以本轮统计LP代替。

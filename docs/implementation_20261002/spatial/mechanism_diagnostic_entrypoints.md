# 三城机制诊断建议入口

日期：2026-10-02。本文件列实施入口，**没有执行以下优化实验，也没有新增效果数值**。先用继承后的原型做机制诊断，再对实际关联输入包通过E0的支路做正式项目实验。原型假设、试验扰动与真实项目字段分栏保存。所有认证或同服务固定投资对照显式调用`freeze_investment_plan(..., relax_reliability=False)`；松弛诊断单列，不作为合格运行结果。

建议由统筹维护一个共同诊断runner，复用`heatplan.io.load_inputs`、`HeatPlanningModel`、`experiments.freeze_investment_plan`及逐场景导出/复算；不要另复制模型内核。每项先登记控制变量、资产身份、服务、时窗/状态边界、预算与容差。

| 机制 | 可复用输入及入口 | 最小两臂与实际开关 | 必须保留的边界/结果 |
|---|---|---|---|
| 乌鲁木齐CHP调峰解耦 | `scenario1_urumqi_public.yaml`继承配置、同一24h接口窗口；后续预登记连续72h事件。修改源配置的热电比区间后构模 | 当前0.20–0.45对固定0.35；保留最低电出力时序、相同源网储、价格/政策/备用。先共同固定投资运行；允许重规划的另列 | 每时热/电、余热直供与提温、库存、购电/发电收益、成本碳、约束残差/solver状态。热电比为原型假设，不称真实抽凝运行域；若直供/热泵共享同源，须消费统筹的共同资源约束及对应可用热量 |
| 固原燃料库存缓冲 | `scenario2_guyuan_evidence_public.yaml`及含居民供暖电价列的年度输入短窗；模型build后在外围添加库存策略限制 | 库存可用对所有库存为0，并禁新库存投资；保留燃料热值、采购/运费/排放、配送/年供应和设备，不删供应链 | 到货/库存/燃耗守恒、系统净电峰、费用碳、服务与不可行时段。循环库存只证明周期机制；非周期寒潮/断供必须设置明确初末库存/电量。物流×0.20、电网×0及概率仍是原型压力设定，不作为历史事实 |
| 武汉区域互联与楼宇响应 | 现有四楼RC候选、已校时连续服务窗；沿用`competition_runner.load_case`的预处理先后顺序，消费返回配置 | 同一零既有容量互联候选许可/禁止；保留逐楼H/C、得热、舒适与初末温、源储电参数。规划候选启禁与已建设管路运行限制分开 | 逐楼RC与温度、区A/B出力/储热、边流量与拥塞、系统电峰/投资、同口径费用碳。冻结已建管道后禁止使用时保留沉没费用，不静默删除资产；上层为系统共享电网，不称独立区域配电 |

前两项保持相同投资/服务身份，第三项规划启禁另列投资变化；零差异、不可行、达到时间上限均保留。实际开关未激活时直接报告无作用，不根据结果调小容量或调整服务制造改善。

真实OSM接入发生在第三项的后续阶段：须先把真实建筑/实际源与参考端点关联并补工程准入，然后每个 `candidate_edges[].name`建立一个管段，采用同名 `candidate_rules`的显式段长。现有武汉四楼与随机六个OSM参考建筑没有该关系，不直接拼接。共享段防重复与有向路径测试本轮已经完成；真实热流、容量、损失与成本效果仍须在获准入的同一模型案例中验证。

数据准入、完整季以及温级/成本碳实验的统筹范围继续以[评分路线](../../score_strategy_20261002/README.md)和[三城专项复审](../../score_strategy_20261002/spatial_scenario_review.md)为准。当前RC只支持合法固定温级，不能直接打开旧内生温级改造接口。

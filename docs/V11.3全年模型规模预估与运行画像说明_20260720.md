# V11.3全年模型规模预估与运行画像说明

> 版本前移说明：V11.4已在本版本的规模先验和覆盖建议基础上，实现逐负荷/最坏COP极端锚点、受约束权重校准、清单式三场景预检和固定投资构模前可靠容量审计；本文保留为V11.3规模与运行画像接口的历史说明。

**版本：** 11.3.0  
**日期：** 2026-07-20  
**范围：** 全年回放求解前的规模先验、实际构模/求解画像、代表时段安全修正建议

## 1. 本轮解决的问题

V11.2已经能判断全年数据能否进入正式回放，但仍缺少三个工程回答：全年模型大约有多大、运行记录中时间花在哪里、代表时段偏差应如何修而不破坏原有概率和极端日结构。V11.3增加：

- 用84小时和168小时两个前缀只构模、不求解，投影8760/8784小时结构规模；
- 分开记录代表时段规划与固定投资回放的构模时间、求解时间和模型结构；
- 输出稀疏矩阵/向量内存和Python构模阶段保守内存代理；
- 把覆盖审计翻译为极端日、季节日或权重校准建议，但禁止自动写回；
- 对MILP求解时间不作线性外推，避免给出不可验证的伪精确承诺。

## 2. 新增接口

`heatplan.chronology`新增：

- `model_structure_profile`：统计变量、整数变量、约束、非零元、密度与内存代理；
- `estimate_annual_model_structure`：双试构模并投影目标时序结构；
- `representative_coverage_recommendations`：把覆盖发现转为非自动建议；
- `AnnualReplayArtifacts.planning_model_profile`与`replay_model_profile`：保存两阶段真实运行画像。

`heatplan.annual_replay_cli`新增：

- `--estimate-model-size`：启用双试构模；
- `--pilot-hours 168`：设置较大试构模前缀；
- `annual_replay_model_size_estimate.json`：全年结构和资源先验；
- `model_execution_profile.json`：正式运行的构模/求解时间与结构；
- `representative_coverage_recommendations.csv`：安全修正建议。

## 3. 示例8760小时先验

基于`data/example_city.yaml`和合成8760小时连续序列，84/168小时试构模得到：

| 指标 | 8760小时投影 |
|---|---:|
| 变量 | 446,785 |
| 连续变量 | 394,219 |
| 整数变量 | 52,566 |
| 约束 | 461,382 |
| 矩阵非零元 | 1,743,303 |
| CSR与向量内存代理 | 40.68 MB |
| Python构模内存保守代理 | 313.26 MB |
| 构模时间中值代理 | 2.14 s |
| 构模宽区间 | 1.06–6.45 s |
| MILP求解风险层级 | very_high |
| MILP求解时间预测 | 不提供 |

`very_high`来自整数变量超过5万的结构分级，只表示年度整数优化需要限时、保留 incumbent 并记录gap，不代表必然不可解，也不是时间预测。

## 4. 168小时实测校验

固定投资短回放仅用于软件与画像校验，不可替代完整年度证据：

| 阶段 | 构模 | 求解 | 变量 | 整数变量 | 约束 | 状态 |
|---|---:|---:|---:|---:|---:|---|
| 代表时段规划 | 0.006 s | 0.309 s | 1,249 | 150 | 1,286 | 最优、零失供 |
| 168小时固定投资回放 | 0.044 s | 0.575 s | 8,581 | 1,010 | 8,868 | 最优、零失供 |

168小时先验与真实回放相比，变量误差约0.14%、约束误差约0.02%、构模时间误差约3.2%。这证明结构投影适合做容量准备；它仍不能推出8760小时MILP的求解时间。

## 5. 代表时段修正策略

现有代表日生成器已强制保留最低温、最大负荷、最大爬坡和最低余热日，并保持代表日权重总和。因此V11.3不对权重做无条件乘法修正。输出规则为：

- 峰值漏捕获：强制最大负荷日；
- 爬坡漏捕获：强制最大爬坡日；
- 严寒漏捕获：强制最低温日；
- 资源低谷漏捕获：强制最低余热/最低可用日；
- 年能量偏差超过10%：重新校准权重或增加季节代表日。

合成年度四个负荷列的诊断性倍率均约1.166，即代表时段年化能量偏低约14.2%。该倍率不会自动应用；正式校准必须同时保持代表天数、场景概率和极端锚点。

## 6. 推荐运行命令

只做全年数据准入和规模先验：

```powershell
$env:PYTHONPATH = "src"
python -m heatplan.annual_replay_cli `
  --config data/example_city.yaml `
  --representative-timeseries data/example_timeseries.csv `
  --annual-timeseries your_hourly_year.csv `
  --output outputs/v11_3_preflight `
  --preflight-only `
  --estimate-model-size `
  --pilot-hours 168
```

正式回放时去掉`--preflight-only`，并设置规划/回放时间上限。运行结束后优先查看`annual_replay_summary.json`和`model_execution_profile.json`。

## 8. 结论边界

规模先验回答“模型装不装得下、预计构模多重、整数风险多高”；短周期画像回答“当前机器和当前配置实际时间花在哪里”。它们都不能替代真实8760/8784小时限时求解，也不能把合成数据包装成三类场景的正式工程结论。
